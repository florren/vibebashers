## Цель
Закрыть требование «сообщение клиенту» (ТЗ 27.3): показать фактические сообщения в том виде, в каком их видит клиент, и честно показать, что клиент ещё ничего не получил.

- Блокирует: [T-229](T-229-scenarij-12-put-obrascheniya-tri-traektorii-yaml.md)

## Что сделать
1. Компоненты эмуляции канала: чат приложения, пост и публичный ответ (переиспользовать компоненты `/feed`), письмо (Mailpit), Telegram, карточка статуса обращения (встроенная копия до готовности `/track`, T-120).
2. Метки времени доставки и «клиент прочитал/ответил» (`client_reactions`); визуально различимы `ack`, `status`, `final`, `gift`, `clarification`.
3. Состояние «пока ничего не получил — ждём решения человека (8 мин)» с таймером; вставки текстов проходят через i18n и маскирование ПДн.
4. Синхронизация шкалы с дорожкой «Внутри банка»: наведение на сообщение подсвечивает породившее его событие и наоборот.
5. vitest и e2e: дорожка совпадает с `notifications`/`external_replies` для сценариев 8 и 1.

## Критерии приёмки
- [ ] Дорожка показывает только фактически отправленное клиенту, ничего внутреннего (поля инцидента, названия систем) — проверяется тестом.
- [ ] Пустое состояние при HITL-паузе и появление сообщения после решения человека.
- [ ] Связь «сообщение ↔ породившее событие» работает в обе стороны.
- [ ] `make lint && make test` зелёные; Definition of Done из AGENTS.md §8 выполнен.
