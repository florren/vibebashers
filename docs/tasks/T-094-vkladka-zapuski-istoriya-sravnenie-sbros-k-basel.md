## Цель
Пользователь видит итоги каждого запуска, запускает сценарий заново с чистыми счётчиками и возобновляет прерванный (ТЗ 4.6, 12.2).

## Что сделать
1. frontend/src/features/runs: таблица запусков (метка, вид/сценарий, статус-бейдж, длительность сим/реал, сигналы, инциденты, SLA, уходы, предотвращённые потери, токены), фильтры по статусу/виду, бесконечная прокрутка.
2. Карточка запуска: параметры, summary (KPI-карточки + мини-графики), кнопки Возобновить (только для paused/interrupted последнего), Стоп, Архивировать, Экспорт JSON/CSV, Удалить (с подтверждением).
3. Сравнение двух запусков: выбор чекбоксами → таблица diff с подсветкой лучше/хуже и подписями профиля LLM (напр. GigaChat-3-Ultra vs mock).
4. Диалог «Новый запуск / Запустить сценарий»: выбор сценария, метка, режим сброса (counters по умолчанию; для сценариев 1, 4, 7 baseline предвыбран и заблокирован), предупреждение о времени восстановления; прогресс восстановления baseline по WS (topic runs).
5. Баннер в шапке при статусе interrupted: «Эмуляция прервана — Возобновить».
6. i18n ru/en для всех строк, стиль по токенам 12.1.

## Критерии приёмки
- [ ] Сценарий 1 запускается из вкладки дважды подряд в режиме baseline: вторая карточка запуска показывает нулевые стартовые счётчики и идентичный summary по завершении.
- [ ] После kill/up контейнера баннер появляется, кнопка Возобновить продолжает запуск, таблица отражает resumed_count.
- [ ] Сравнение двух запусков показывает diff; экспорт скачивает файл.
- [ ] `make lint && make test` зелёные; Definition of Done из AGENTS.md §8 выполнен.
