## Цель
Демонстратор ведёт показ с экрана: следит за новым сигналом вживую, повторяет завершённый путь, листает стадии с тезисами (ТЗ 27.4).

- Блокирует: [T-229](T-229-scenarij-12-put-obrascheniya-tri-traektorii-yaml.md)

## Что сделать
1. «Следить»: подписка на последний сигнал выбранного происхождения (`/api/journey/latest`) и на WebSocket; стадии появляются по мере событий, ожидаемые — пунктиром; автопереключение на новый сигнал по желанию.
2. «Повтор»: воспроизведение записанных событий с реальным или сжатым темпом, пауза, шаг назад/вперёд; нового запуска агента не создаёт (бейдж «повтор»).
3. «Ведущий»: крупная раскладка, `←/→`, тезисы из `presenter_notes_ru`, таймер блока демо, скрытие технических деталей; горячие клавиши в справке `?`.
4. Входы «Показать путь»: кнопка в модале «Ввести сообщение клиента» (после отправки), на `/feed` после ответа, в карточке инцидента, в «Под капотом», в результатах поиска, пункты меню демонстратора для сценариев 1, 8, 9, 11.
5. vitest на машину состояний режимов; e2e: «Следить» ловит сигнал, введённый через модал.

## Критерии приёмки
- [ ] Новый сигнал, введённый жюри, появляется на экране пути ≤ 1 с после первого события.
- [ ] Повтор завершённого пути воспроизводится без обращения к агенту; режим ведущего переключается клавишами.
- [ ] Все входы «Показать путь» ведут на корректный `ref`.
- [ ] `make lint && make test` зелёные; Definition of Done из AGENTS.md §8 выполнен.
