## Цель
Живая лента с фильтрами, бейджами классификации, быстрым переходом к инциденту/клиенту.

## Разделы ТЗ (docs/TZ.md)

- `events/ws/message.schema.json (signals)`

## Зависимости

- Блокирует: [T-144](T-144-proverka-proizvoditelnosti-profilya-demo.md)

## Что сделать
1. Виртуализированный список, фильтры по контракту, поиск, подсветка критичных и churn_intent, иконки каналов, бейдж «fallback/mock» для запусков без LLM.
2. Карточка сигнала (drawer): текст, классификация с rationale_ru, решение, связанные инциденты, запуски агента (ссылка в «Под капотом»), уведомления.
3. Жюри-режим: форма ввода сигнала с выбором клиента/канала.

## Критерии приёмки
- [ ] Новый сигнал появляется в ленте ≤ 1 с; 5 000 сигналов прокручиваются плавно.
- [ ] Все фильтры контракта работают и сохраняются в URL.
- [ ] `make lint && make test` зелёные; Definition of Done из AGENTS.md §8 выполнен.

## Как проверить
```bash
npx playwright test e2e/signals.spec.ts
```
