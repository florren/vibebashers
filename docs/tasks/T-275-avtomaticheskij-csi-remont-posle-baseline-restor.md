## Что сделать
1. Подключить единый CLI repair_csi до restore_finished и старта сценария; логика ремонта не дублируется.
2. Привязать async dump/restore и ремонт к переданному соединению с сохранением auth.
3. Регрессии старого/полного архива, повторов, неизменности данных и явного отказа без finished/start.

## Критерии приёмки
- [x] Restore 440/480 автоматически даёт 480/480; повтор не накапливает CSI, полный архив — no-op.
- [x] Прежние решения, проводки, время/RNG и архив сохраняются; ошибка блокирует finished и новый запуск.
- [x] Другой глобальный DATABASE_URL не перенаправляет dump/restore или ремонт в другую БД.
- [x] `make lint && make test` зелёные; Definition of Done из AGENTS.md §8 выполнен.

## Как проверить
```bash
make lint && make test
test_baseline_csi_auto.py; test_baseline_restore.py; PG16 изолированный restore
```
