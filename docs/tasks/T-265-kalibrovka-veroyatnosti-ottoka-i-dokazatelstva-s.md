## Что сделать
1. Сохранить версию и время существующего скора classification.churn_risk в шаге агента; LLM-промпты/схемы и ключи кассет не менять.
2. Воспроизводимая демо-калибровка на синтетических контрольных исходах за 7 сим-дней, disjoint train/validation, метрики, checksum и допуск источника. Рабочий набор требует собственных согласованных данных.
3. Версионированная политика штрафа и append-only журнал деклараций с временными доказательствами. go без доказательства суммы не даёт; неизвестный/поздний исход и отзыв исключают оценку.
4. Один риск на клиента за запуск, один штраф на сделку; возвраты по всем кейсам; unknown остаётся null. UI показывает оба контура и provenance, форму/историю доказательства.
5. Golden/calibration, unit/integration/frontend tests; replay совместимость, миграция 0008, docs и ru/en × light/dark.

## Отчёт субагента
Ветка: `codex/finance-evidence`; PR связывается с GitHub #89 / E24 #87.

По прямому уточнению заказчика выполнен демо-прототип с обоими контурами рядом. Демо-скоры и контрольные исходы синтетические; они проверяют механизм, а не реальное качество NLP. Рабочий контур подготовлен к подключению отдельно согласованных наблюдений и политики. Реальных наблюдений и бизнес/юридического согласования в поставке нет: рабочие P/штраф/net остаются null. Критерий реального юридического подтверждения не объявляется выполненным; это граница согласованного демо-среза, ADR-0014.

Реализованы provenance скора без изменения LLM-схем/кассет, воспроизводимая 7-дневная калибровка, GET assessment, POST evidence, неизменяемые версии с идемпотентностью, временной допуск и отзыв. Первый риск клиента выбирается до фильтра дат; штраф — один на сделку, возвраты — по всем кейсам, неполные возвраты исключают net. Денежных проводок и решений HITL новый API не создаёт.

Контракты: OpenAPI 1.5.3 (FinanceAssessment/CaseProof/EvidenceBody и связанные схемы), миграция 0008, additive таблица financial_evidence. Сгенерированы копии БД, SQLAlchemy/TS. Cross-layer L1/L2/L3/L4 прямо разрешён заказчиком.

Проверки: make lint/test, targeted calibration/evidence regression, contracts/drift/i18n/owners --allow-cross, генераторы воспроизводимы; frontend lint/typecheck, 122 Vitest, production build. Покрытие новых economics-модулей 93 % суммарно. PostgreSQL локально 18.6 UTF8/UTC; CI проверяет PostgreSQL 16. Replay-сценарий сохранён. Живой QR через GigaChat: normalize/instant_decide ok, модель GigaChat-3-Ultra:32.9.16.9, TLS включён, только синтетические данные, без записи кассет.

Отчёт, показатели, трасса и ru/en × light/dark/mobile скриншоты: [finance-calibration-2026-10-29](../benchmarks/finance-calibration-2026-10-29/README.md). Новых зависимостей/переменных окружения нет. До запуска обновлённого стенда требуется `make migrate`; рабочая БД в ходе разработки не изменялась. Откат приложения сохраняет историю таблицы.
