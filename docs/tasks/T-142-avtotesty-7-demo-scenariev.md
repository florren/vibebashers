## Отчёт субагента
- `backend/tests/scenarios/test_scenarios.py` — параметризованный тест по всем сценариям с секцией `inject` в `data/scenarios/*.yaml` (9 из 11; сценарии 09/10 помечены `requires: B07` и проверяются `test_all_scenarios_listed`). Каждый сценарий: отдельный `sim_run` → инъекция сообщений (клиент по описанию + свежая неуспешная операция) → `process_signal` на mock → `evaluate` ожиданий из YAML.
- Проверяемые ожидания: флаги, приоритет, команда/соисполнители, уточнение/отложенность, дедупликация в один инцидент + `mass_impact`, правило `RULE-QR-FEE-001`, тональность/скрытый негатив, роль эскалации, «под капотом». Ожидания пакетов B05–B09/B14 (подарки-эконом., превентивные уведомления, карта, возврат) помечены «не проверяется: <пакет>» и не валят тест.
- Тот же движок доступен на стенде: `GET /api/scenarios`, `POST /api/scenarios/{id}/run`, CLI `scripts/scenario_check.py` (`make scenario ID=…`), результат сохраняется в `scenarios.last_result`.
- Попутно исправлено в агенте по итогам прогонов: гонка создания инцидента при параллельных жалобах (advisory lock + повторная проверка в `act`), подмена кода ошибки из контекста, когда текст о другом (`ERROR_CODE_WORDS`), уточнение для неопознанного клиента и для подозрения на мошенничество без подтверждения антифрода (ожидание 24 ч), уточнение при сарказме без конкретики, флаг `public` вместо невалидного `public_shaming`; mock: «двойное списание» → техсбой, фразы «менять банк», «отказали».
