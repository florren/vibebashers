## Что сделать
1. По матрице покрытия: ≥ 1 сигнал на каждую комбинацию тип × продукт × канал, ≥ 3 инцидента на каждую ячейку SLA, все сегменты/округа/психотипы; статусы распределены (часть открыта, часть закрыта в срок/с опозданием/с регрессией/отклонена).
2. Для закрытых — полный цифровой след: статусы, артефакты команд (RCA, решение о фиксе, отчёты д3/6/9 для hard/low, релиз, проверка), уведомления клиенту, задачи-подарки.
3. Классификация/решение прошлых сигналов — через mock-провайдер (без расхода токенов), agent_runs с пометкой kind=agent, outcome=completed, profile=mock.
4. Состояния клиентов и churn_events по модели поведения (T-161) в «ускоренном» прогоне; ≥ 10 инцидентов account_closure; регрессии связаны с инцидентами.
5. Пересчёт incident_economics (T-131) и запись матрицы покрытия в settings.coverage.
6. Вся предыстория помечена run_id базового запуска (sim_runs.kind=baseline, создаётся сидом первым шагом); после сида сервис запусков (T-040) фиксирует снимок baseline.
