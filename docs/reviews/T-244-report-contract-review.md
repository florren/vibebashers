# T-244: read-only отчёт кабинета, API 1.5.26

Статус: реализация подготовлена, human contract review и CI ещё требуются. Это отдельная карточка/ветка; база — T-242 `5b34a5f`. API 1.5.25 зарезервирован за T-039: при композиции сохранить его изменения, а не заменить версию поверх потерянного diff. Новых DDL, зависимостей, ролей/RBAC или HITL/денежных политик нет.

## Контракт и источник

`GET /api/cabinet/report` реализован вместо 501. Существующие product_line/period/run_id/format и preset headers сохранены; добавлены `lang=ru|en` (по умолчанию ru), типизированный `CabinetReport`, MIME настоящего XLSX и ошибка 413. Поведение current/baseline/all/числового запуска и soft/strict полностью совпадает с T-241 overview; проверка происходит до чтения экспортируемых данных.

Одна READ ONLY REPEATABLE READ транзакция: текущий overview, предыдущее равное непересекающееся окно, сохранённые incident facts/economics, маскированные сигналы, версии реально записанных rule_evaluations. Никаких LLM, compute_incident/compute, записей, сетевых каналов или материализации денег из GET. Предыдущее окно непересекающееся и точно равное по длительности: те же run/product-line predicates и фактические numerators/denominators. Дельты всех шести KPI: counts, процентные пункты известных долей, разница сохранённых денежных оценок; delta_unit задаёт единицу. Нет знаменателя/полной экономики — NULL. Когорты выбираются по received_sim/created_sim, используются последние сохранённые статусы/оценки, а не реконструкция состояния на конец старого окна. Полнота окон не подтверждена; delta не выдаётся за изменение CX/популяционного уровня негатива или причинный финансовый эффект. Нормативные пороги не придуманы. CSI index отсутствует явно; известные counts остаются в overview.

Основная тема — самый частый записанный SignalType с локализованным названием и явным числом известных типов/полным cohort; NULL и legacy unknown не выдаются за классификацию. Top-5 — приоритетные записанные инциденты (attention, связанные клиенты, id), а не выдуманный финансовый рейтинг. Число клиентов — только по связанным клиентским сигналам; anonymous/отсутствующие связи дают NULL полного покрытия, отдельный identified count. Нет догадок по mass_impact. Действие берётся из resolution_summary либо последней записанной team_actions той же run/incident с детерминированной локализованной подписью; только при отсутствии обоих источников — «не записано». Attention показывает до 10 инцидентов и до 10 red-word сигналов, с общими counts и записанной командой либо unknown. Полный набор сигналов сохраняется в экспорте. SLA risk — только latest native sla.warning того же run+incident с совпадающим deadline, строго после последней incident_status_history стадии и release. Терминальные, stale/reopened, неоднозначные same-clock и неизвестные стадии не объявляются текущим риском. Есть sla_warning_count/note и ссылка на фактический event_id. SlaEngine пока дедупит warning один раз на run/incident (sla.py423–426); после повторного lifecycle без нового native evidence риск остаётся unknown. Producer/его пороги не меняются. Служебные proactive anchors исключены только из customer facts; настоящие incident/economics facts сохранены.

## Лимиты, XLSX и точные деньги

- Не более 10 000 сигналов, 10 000 инцидентов и 10 000 run references на отчёт; превышение — 413, без усечения. Run list читается с LIMIT 10001 для обнаружения превышения.
- JSON ≤ 5 MiB; тот же bound проверяется перед XLSX. XLSX также ≤ 5 MiB. Непредставимый в XML/Excel текст (недопустимые XML controls / ячейка >32767 символов) — явный 413 с предложением JSON, без скрытой обрезки. Проверка выполняется до открытия XML writers.
- Настоящий openpyxl workbook: Главное, KPI, Сигналы, Динамика, Источники, Регионы, Методика. Строковые ячейки принудительно имеют тип text: `=`, `+`, `-`, `@`, tab/newline не становятся executable formulas/hyperlinks. Источники — только доверенное текстовое имя площадки, без source_url/free meta; сводки контактов маскируются общим privacy helper.
- На локальной report connection JSONB numeric декодируется в Decimal. `overview` numeric shape совместим с существующим API; authoritative lossless поля — `money_exact.kpi/previous/daily/monthly` (decimal strings или NULL). Для значений и денежных delta есть отдельные точные строки; XLSX денежные cells используют именно эти строки: Excel numeric теряет копейки после 15 значащих цифр. Доли в XLSX имеют процентный number_format, delta долей — п.п.; daily экспортирует и loss, и prevented. Fraction shares остаются numeric; их roundtrip проверяется с abs1e-14, деньги — строго exact.
- Report UI/print форматирует decimal strings через BigInt, без Number(decimal-string). Компактная подпись соседствует с видимой полной точной суммой; это форматирование, не новая формула dCLTV. Подписи оси compact и проверяются по реальным bbox SVG text (включая большой aggregate), неизвестная денежная серия не создаёт нулевую ось; месячные известные counts сохраняются. Графические оси/координаты — визуальное приближение; исходные точные ряды доступны в JSON/XLSX.
- Boundary fixture использует сумму допустимых numeric(14,2), а не невозможную >15-digit одиночную колонку. Предыдущее окно содержит явно сохранённые известные нули, текущее — крупные допустимые суммы с fixture-adjustment до .99, чтобы целое число строк не скрыло потерю копеек. Значения и delta проверяются exact; это transport-boundary fixture, не калиброванные оценки. Тест проверяет, что float действительно теряет точность, затем exact source→JSON→XLSX без money tolerance.

## Печатная форма

`/cabinet/:productLine/report` — snapshot-страница без глобального Shell/живого WS runtime. Нет глобальных feed/SLA/digest запросов. Выбранные preset/направление/период/run сохраняются. Каждая загрузка — новый snapshot с датой; атомарность между двумя отдельными HTTP запросами не обещается.

Три A4 страницы: выводы и ≤6 KPI → три SVG ECharts с выводами/маркерами/штриховкой → Top-5, attention, методика. Печатные описания и длинные списки ограничены явно, полные записи доступны в экспорте; неизвестное не заменяется 0. Источник текста сохраняется на исходном языке; интерфейс/шаблоны ru/en. Формулы — примеры из сохранённого breakdown, без восстановления арифметики. Версии — из записанных rule_evaluations, не текущая версия правил задним числом. Дата — симуляционное время, Europe/Moscow, независимо от browser timezone.

PDF — только window.print()/Chromium page.pdf(); серверного PDF нет. Named @page и print reset ограничены report route, другие экраны не меняются. Белая чёрно-белая бумага одинакова в dark/light; экранные controls наследуют выбранную тему. Footer содержит дату и номер страницы.
