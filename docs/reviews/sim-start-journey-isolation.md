# Исправление Start и границы ручного Journey

## Требование и причины

Уточнение пользователя: общая симуляция запускается кнопкой Start и исполняет весь
нативный мир. Профиль на странице Journey относится только к вручную введённому
там обращению, не переключает общий запуск и не подставляет входы сценария.

Обнаружены три связанные причины:

1. Header предпочитал старый WebSocket snapshot свежему ответу REST после reset.
   Вместо Start мог отправляться Resume, а ошибка управления не показывалась.
2. Journey использовал глобальный `/api/demo/execution`, переключавший run и часы
   симулятора. Локальный выбор сценария становился настройкой всего банка.
3. Нативный TeamEmulator отключался при любом `demo_execution.enabled`, включая
   обычный режим simulation. Его заменял отдельный сценарный исполнитель.

## Изменение

- REST, WebSocket и управление синхронизируют общий Query cache состояния.
  Ошибка управления видна, выполняется повторное чтение состояния.
- Обычный running World исполняет нативные генераторы, TeamEmulator и RNG.
  Отдельный исполнитель команд остаётся только у явного legacy demo.
- Journey сохраняет draft профиля в UI. Только отправка ручного сообщения
  создаёт отдельный non-current live run через штатный ingest/normalizer.
  YAML-входы и доказательства выбранного сценария не инжектируются.
- Дополнение наследует сохранённый профиль родителя; смена draft переводит
  редактор в новое обращение, сохраняя набранный текст. Повтор запроса не создаёт
  новый run. Чужой родитель и профиль у другого источника отклоняются.
- Время ручного кейса строится по его собственным уже записанным фактам.
  Запланированные due, чужие run и глобальные часы не продвигают его.
- Потерянный NOTIFY и прерванное durable продолжение восстанавливаются через
  штатное владение AgentRun. Общий SLA tick ограничен своим run; очередь
  дополнений использует время сообщения клиента.
- Ручные HITL decision/feedback Journey используют время собственного кейса,
  даже если общий мир продвинулся. Явный внутренний demo override и остальные
  режимы сохраняют прежний выбор часов.

API/DDL, формулы, ставки, финансовые лимиты и полномочия HITL не меняются.
Существующая история не переписывается. Legacy explicit scenario API и
публичный персональный чат сохраняются.

## Проверки

Регрессии проверяют настоящий фоновый `_start_loop`: два независимо
зафиксированных тика и реальные операции, Pause/Resume/Stop. Старый код даёт
RED. Дополнительно проверяются изоляция Journey, нативные Mock-графы, собственные
Team outcomes, потеря уведомления, restart и границы SLA/дополнений.

Собранный UI проверен в настоящем браузере на отдельном PostgreSQL-банке с
Mock LLM и нативными Simulator/AgentService: Start до открытия Journey,
продвижение времени и новые сигналы; Pause; выбор профиля и ручное сообщение
при неизменных глобальных часах; затем Resume/Pause/Stop общего мира.
Реальные LLM и внешняя доставка для этой проверки не вызываются.

Итоговые численные результаты полного набора и CI фиксируются в PR.

## Внедрение и откат

Обновляются backend и собранный frontend вместе. Миграций, seed, reset и
автоматического переноса старых глобальных demo-сессий нет. Перед обновлением
проверяются тихое состояние, резервная копия и сохранение `.env`.
Откат — предыдущий образ приложения без восстановления/изменения банковской БД.
