# T-031: RNG текстов при восстановлении мира

`World` создавал `TextGen(rng.randrange(...))`: конструктор тратил случайное
значение общего RNG и создавал второй `random.Random`. В `sim_state` сохранялся
только первый. После восстановления `World` брал другой seed, поэтому расходились
и тексты, и следующие случайные значения операций/сбоев.

`TextGen` теперь принимает существующий `random.Random` (в том числе `SimRng`)
или прежний целочисленный seed. Runtime передаёт свой `SimRng` без нового draw;
standalone seed/corpus callers по-прежнему получают независимый seeded generator.
Формат `sim_state.rng_state`, БД, API и вероятности/финансовые правила не меняются.

Три новых regression tests используют настоящий `World` и `SimRng`: конструктор
не меняет RNG state; после25прогревочных генераций dump/load и новый World дают
те же40текстов, random/poisson draws и конечный RNG state; старый int-seed API
сохраняет детерминизм и независимость экземпляров. Существующие textgen tests
сохранены. Targeted7 passed0.39s; полный unit1056 passed/18skip29.01s.
Оставшиеся проверки полного make test/CI отмечаются отдельно после завершения.

Гарантия относится к сохранению состояния новой версии. Старый private TextGen
RNG в БД отсутствовал, поэтому его неизвестное будущее состояние восстановить
задним числом невозможно. Новые тексты при одинаковом seed могут отличаться от
предыдущей версии: теперь они потребляют единый, сохраняемый поток RNG.

Это не доказательство сохранности всех таймеров мира: `World.pending` пока живёт
в памяти. Её durable замена входит в T-161 и общий аудит восстановления T-041.
Не утверждается, что этот небольшой diff сам по себе завершает восстановление
всех доменных процессов. Откат — обычный revert без изменения схемы; он вернёт
исходный дефект private RNG. Рабочая БД и реальные внешние сервисы не менялись.
