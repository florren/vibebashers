# T-050: durable accounting, подготовка P2

## Проверенный foundation checkpoint

Основа private ledger добавлена отдельно от подключения провайдеров. На этом checkpoint production HTTP admission не переключён: `accounting.service()` ещё не вызывается провайдерами. Карточка T-050 остаётся `in_progress`; API1.5.21, operator CLI, wire hooks, публичные остатки и финальные full/coverage/CI ещё впереди. Нельзя считать этот checkpoint исполнением всей карточки или окончательным финансовым approval.

Источник — миграция0016 `contracts/db/migrations/0016_llm_accounting.sql`; mirror/schema/models генерируются штатно. Namespace `llm_runtime` исключён из банковского pg_dump и не имеет FK к восстанавливаемым public configuration/AgentRun. Данные inference attempts, неизвестный расход и reconciliation переживают банковский restore. Downgrade forward-only: operational counters не удаляются автоматически. Отмена не возвращает reservation. Сбой между commit reservation и отправкой HTTP консервативно считается возможной попыткой; exactly-once для DB+HTTP не заявлен.

Physical credential определяется private keyed verifier; credential bytes/промпты/ответы в ledger не записываются. Смена APP_SECRET приводит к безопасному отказу до reviewed identity migration. Canonical aliases одинакового physical key с одинаковыми действующими лимитами делят один ledger. Конфликтующие active limit configurations блокируют admission: min/max policy не вводится. Выбранная explicit binding повторно проверяется до admission; fallback к env не добавлен.

`llm_profiles.quota_uid` — private UUID конфигурации, включённый в opaque config fingerprint. Он сохраняется при rename/правке лимита и банковском restore той же конфигурации. Новый профиль, даже с повторно использованным числовым ID, получает новую unknown quota identity. UUID отсутствует в public profile API, settings JSON export и AR/SimRun role snapshots. Private банковский dump содержит этот configuration UUID для корректного restore; operational namespace в dump отсутствует. Public config ID разрешается во внутренний quota scope под configuration lock.

Краткая транзакция после ordered configuration/profile/credential locks читает реальное `clock_timestamp()` в UTC, проверяет allowance и атомарно резервирует key/profile daily attempt. Session lease сериализует неопределённость расхода одного physical key между процессами; сетевой вызов не держит SQL transaction. Повтор UUID reservation не разрешает повтор HTTP. OAuth/GET модели/баланс пока не подключены и не выдаются за inference RPD.

Missing usage не является0. Validated cumulative observations прибавляют delta один раз; известный floor сохраняется при stream failure/повторе observations. Незавершённая reservation требует истечения deadline и отдельного acknowledge в reconciliation. Операционное начало не создаёт known0: budgeted unknown calls fail-closed. Legacy `tokens_used` сохраняется как `legacy_tokens_hint`, а не подтверждённый wire floor: старый health path мог присвоить ему размер limit. Reconciliation требует явного `acknowledge_unknown_origin`, source=`operator_declared_app_usage`, timestamp текущих UTC суток, UUID и не уменьшает подтверждённый app-observed floor. Audit сохраняет прежние source/known/hint и явное подтверждение оператора. Автоматический новый бюджет «с момента cutover» не вводится.

## Wire checkpoint (отдельный follow-up)

GigaChat и OpenAI-compatible structured/stream используют durable admission непосредственно перед каждым inference POST; OAuth/GET не увеличивают RPD. Native-format400, transport errors, JSON repair и SSE проходят реальные hooks. Token bucket RPM остаётся перед выбранным live candidate, прежние deadline/close/offline/no-fallback-after-prefix assertions сохранены; только для durable providers logical in-memory RPD больше не конкурирует с authoritative wire RPD. Остальные custom/legacy limiter callers сохраняют прежнюю семантику.

Любой live structured response без validated usage теперь bad_output с usage=None, включая free/local; validated0 допустим. DTO успешного Usage не сделан nullable. Stream запрашивает include_usage и при отсутствии metadata завершается явной ошибкой после уже отданного безопасного prefix; fallback не смешивает источники. Cumulative usage прибавляется по delta, reported total сохраняется отдельно от p/c, total ниже суммы отклоняется. Giga health quota denial не присваивает durable key фиктивное tokens_used=limit; старый standalone KeyPool остаётся совместимым.

Единственное no-DB runtime исключение — существующий отдельный T048 fixed synthetic smoke CLI: собственный cap6 inference и прежний cap6 ВСЕХ HTTP/3 fixedmodels/max128 output/fixedprompt, прежний budget loader. Оно не выдаётся за app-wide durable accounting, не вызывается автоматически и здесь не исполнялось. Protocol unit tests используют test-only storage adapter; настоящий PostgreSQL+FakeHTTP проверяет production default. APP_ENV не отключает accounting.

## API21/operator checkpoint (следующий отдельный follow-up)

OpenAPI1.5.21 добавляет только optional read-only поля LlmApiKey: `observed_tokens_floor`, `usage_known`, `usage_source`, `usage_as_of`, `requests_known`, `requests_day`, nullable `tokens_remaining`/`requests_remaining`. Старое `tokens_used` до reconciliation сохраняет legacy hint (включая исходную migration assertion17); при unknown оно не означает полный расход. После explicit reconciliation показывает declared/app-observed floor. UI обязано отображать unknown и не вычислять remaining из hint. Config/profile/AR projections не получают private UUID/verifier/ciphertext. Existing env card получает readonly ledger projection по private physical identity; новых balance/usage HTTP запросов не добавлено, прежнее hint-based card dedup здесь не менялось.

Operator CLI: `python -m app.llm.accounting_cli status --profile-id ID --key-id ID`; reconciliation требует `--reconciliation-id UUID --as-of ISO_UTC --tokens-used N --requests-today N --profile-requests-today N --confirm --reviewed-unknown-origin`. `--acknowledge-orphans` отдельно подтверждает expired unfinished attempts. Вместо key ID можно указать фиксированный `--env-slot gigachat1|gigachat2|openrouter|local`; endpoint/source проверяются, explicit bound profile не получает env fallback. Raw credentials в argv не принимаются; ошибки parser/DB/provider не печатают вход, ключ, DSN или upstream body. Отсутствующие observation/confirmation проверяются до чтения конфигурации. CLI не делает HTTP и не создаёт дополнительный budget origin; reconciliation библиотека сохраняет source/as_of/provenance audit.

Совместимые public counter columns теперь derived mirrors private ledger после reconciliation; резервирование/usage не увеличивают их второй раз. Restore обновляет mirrors из сохранённого operational namespace до возобновления writers. До reconciliation legacy hint остаётся на месте; он не становится подтверждённым floor. Окончательное устранение additive writer/forecast в BenchService оформляется следующим follow-up.

## Bench/source convergence checkpoint

BenchService больше не начисляет physical usage из результата benchmark: `record_key_usage` только синхронизирует derived mirrors уже учтённого wire ledger. Forecast использует operational UTC profile day, server remaining/known, дедупликацию физических aliases и явный отказ при неизвестном budget/conflicting aliases; process-local limiter reset и cached usage не возвращают allowance. Private grouping IDs не входят в Forecast/BenchRecord/JSON/CSV. Прежние isolated helper callers без новых metadata сохраняют старую совместимость.
