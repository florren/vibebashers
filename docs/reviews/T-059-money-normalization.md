# T-059 follow-up — review financial input boundary

Отдельный focused defect fix, требует ревью до merge. Политики возврата, HITL, лимиты, денежная арифметика и контракты не меняются.

## Дефект и конкретный diff

Обе прежние регулярки (`nodes.regex_hints`, `MockProvider.analyze`) разрешали только digits/whitespace перед рублёвым маркером. На `5472.45 рублей` поиск начинал новое совпадение после точки и выдавал `45.0`. Затем Mock normalization перекрывал правильные подсказки своим значением по тому же ошибочному правилу.

Теперь оба пути вызывают `app/amounts.py`. Полный числовой токен разбирается через `Decimal`, без округления и арифметики float. Поддерживаются integer (включая 0 и одну цифру), decimal comma/dot с 1–2 знаками копеек, группы тысяч по 3 цифры с обычным пробелом/NBSP/narrow NBSP/thin space, прежние рублёвые маркеры. Копейки, хвосты некорректной группы/дроби, даты, отрицательные суммы и иные валюты не превращаются в самостоятельный положительный integer.

Прежняя семантика нескольких сумм сохраняется: первое полное рублёвое упоминание. В `Оплатил по QR 5472.45 рублей, списали комиссию54.72руб` hint — 5472.45; если первой написана комиссия 54.72, hint — 54.72. Parser не выбирает «сумму возврата» и не подменяет подтверждённое бизнес-правило.

## Совместимость и точность

- `5472.45`/`5472,45` теперь дают 5472.45 вместо 45. Нулевой/однозначный amount сохраняется, не теряется из-за truthiness.
- Некорректные/неоднозначные `123.456 руб`, `12 34 руб`, `1,234.56 руб`, отрицательные значения больше не дают частичный hint. Это намеренное изменение интерпретации financial input; оно не обещает распознавание международных separator conventions.
- Exact helper возвращает Decimal. В существующий JSON normalization contract hint преобразуется в finite float только на выходе; unrepresentable Infinity не сохраняется. Произвольные огромные суммы в JSON float не гарантируют точность копеек. Финансовым основанием остаются `numeric(14,2)` операции/проводки БД, а не этот hint; финансовая арифметика здесь не выполняется.
- LLM entities по-прежнему имеют существующий приоритет над regex hint. Политики confidence/clarification/refund/HITL не менялись. `RE_AMOUNT` — удалённая внутренняя дублирующая регулярка; публичные интерфейсы API и event schema не меняются.

Parent установил отдельные причины fixture/данных T-017: выбор клиента/операции без segment/window constraints и QR failure code без положительной комиссии. Эти изменения находятся в другой ветке; assertions/cassettes T-017 здесь не редактировались.
