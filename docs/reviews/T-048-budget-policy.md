# T-048 — отдельное ревью политики расходов внешних LLM

До merge требуется явное ревью этой политики. Это бюджет внешнего OpenRouter API; клиентские деньги и HITL не изменяются. DB/API/event contracts не меняются.

## Подготовленный diff

- Каждый новый платный completion, смена формата после 400, исправляющая попытка и stream проверяют актуальный `settings` key `llm`, поле `openrouter_budget_usd`. Поля нет → `OPENROUTER_BUDGET_USD` (по умолчанию 10). Значение 0 запрещает платные вызовы. Ошибка БД, отрицательное/нечисловое/неограниченное значение запрещают их с `ProviderError(kind=quota)`.
- Перед каждым платным запросом читается `GET /api/v1/key`. Отсутствующий, отрицательный или нечисловой `usage` больше не означает 0. Известный `usage >= budget` либо исчерпанный/некорректный `limit_remaining` запрещают completion/stream. `limit_remaining=null` — допустимый неограниченный лимит ключа, но budget и usage всё равно обязательны.
- Из budget preflight исключены только IDs с суффиксом `:free`. `openrouter/owl-alpha` без этого суффикса больше не обходит проверку на основании hardcoded списка: это намеренное ужесточение политики, не утверждение о текущей цене модели.
- При отсутствии корректного token usage в платном ответе/последнем stream chunk фиксируется явная ошибка `bad_output`, не успешный ответ с нулевым расходом. Следующий запрос снова обязан получить известный долларовый расход через `/key`. HTTP/transport ошибки не объявляются бесплатными: usage ошибки остаётся неизвестным; перед повтором действует тот же preflight. Ранее подтверждённые токены не теряются при запрете исправляющей попытки.
- Balance UI сохраняет контрактное имя `balance_usd`, но `/key.limit_remaining` — остаток лимита конкретного ключа, не обязательно весь баланс аккаунта. Дневной RPD берётся из `free_model_daily_requests.limit`, если upstream его сообщает; старые payload сохраняют legacy fallback 50/1000.

## Границы гарантии

Это preflight cutoff по опубликованному OpenRouter `usage` за всё время, а не атомарная денежная резервация или потолок стоимости ответа в полёте. Параллельные запросы/другие приложения на том же ключе и задержка обновления `/key` могут превысить остаток между проверкой и расчётом upstream. Для жёсткого денежного потолка необходим также server-side лимит ключа OpenRouter; приложение его не изменяет. Прогноз конечной стоимости/политика резервирования требуют отдельного согласования, здесь не выдумываются.

Stream-интерфейс возвращает текст, не Usage. При отсутствии usage после уже выданных токенов ProviderChain сохраняет существующую семантику: пишет `llm_stream_broken` с явной причиной и не подмешивает другой ответ. Успешный токеновый поток не доказывает известный расход; следующий платный запрос допускается только после `/key` preflight.

## Проверки и источники

72 целевых unit tests SDK/budget/chain прошли на `httpx.MockTransport`, без реальных моделей. Отдельно проверены unknown usage, нулевой/некорректный бюджет, сбой БД, повторная проверка перед retry, сохранение известного usage и отсутствие usage в stream.

Официальная семантика `usage` (all time), nullable `limit_remaining`, daily request limits: https://openrouter.ai/docs/api/reference/limits . SDK: https://developers.openai.com/api/reference/python ; установленный openai 2.54.0, public AsyncOpenAI API и исходники auth/stream проверены локально.
