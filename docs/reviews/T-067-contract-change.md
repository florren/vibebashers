# T-067 — contract-change: API 1.5.12

Техлид согласовал в чате параметры: до 5000 символов и 20 ручных запросов в минуту. Merge допускается только после проверок конкретного обновлённого diff.

## Конкретный diff

- `POST /api/agent/compare`: `text` ограничивается `minLength: 3`, `maxLength: 5000` ; для `POST /api/signals` верхняя граница расширена с 4000 до 5000.
- `POST /api/signals` и `POST /api/agent/compare`: документирован ответ 429 в формате Problem; `Retry-After` сообщает число секунд до освобождения общего лимита 20 запросов/мин на единственный backend-процесс.
- Версия OpenAPI 1.5.11 → 1.5.12; TypeScript types регенерированы из OpenAPI.

## Совместимость

Сужение допустимого текста сравнения — несовместимое изменение для клиентов, отправлявших менее 3 или более 5000 символов: теперь ответ 422 до вызовов LLM. Номер patch отражает текущую нумерацию проекта и не делает изменение обратно совместимым. Миграция: валидировать длину до отправки, ограничить форму 5000 символами. Проверка после trim дополнительно отвергает пустой ввод.

429 — новый наблюдаемый исход при превышении лимита. Клиентам нужно обработать Problem, показать задержку `Retry-After`, повторять после ожидания. Лимит общий для обоих ручных endpoint; отдельный compare также расходует одну попытку. Неуспешная бизнес-валидация после входной валидации может расходовать попытку.

Успешные response-поля не меняются. Ранее фиктивные/null IDs сравнения заменяются настоящими IDs записей `agent_runs(kind=compare)`. Схема БД и event contracts не меняются. Запуски сравнения исключаются из operational KPI основного агента; диагностический отчёт продолжает показывать их отдельным kind.

Реальные LLM, UI T-109 и критерий ≤60 с на Ultra проверяются отдельно и здесь не заявлены как выполненные.
