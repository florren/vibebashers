# Проверка готовности перед install.sh --reset

## Дефект и граница исправления

Установщик выполнял `docker compose down -v --remove-orphans` до подготовки Vosk и `up --build`. Поэтому ошибка модели, Docker build или скачивания образа обнаруживалась уже после удаления томов и контейнеров. Остановленный посторонний контейнер также мог удерживать один том, пока остальные тома уже были удалены.

Теперь при явном `--reset` до `down` выполняются:

1. Подготовка модели, если она требуется выбранными флагами.
2. Чтение resolved Compose config без вывода его содержимого: оно может содержать секреты.
3. Проверка держателей управляемых named volumes из resolved-модели выбранных profiles. Допускаются только обычные контейнеры активных сервисов этого Compose project; посторонний или one-off контейнер, включая остановленный, останавливает установку с его ID и именем тома. Контейнеры автоматически не удаляются.
4. `compose build` с выбранными profiles и получение только отсутствующих образов активных сервисов. Уже имеющиеся образы не обновляются через `pull`.

Только после успеха выполняются прежний явный reset и `up --no-build --pull never`. Установка без `--reset` сохраняет прежний способ запуска. Контракты, схема и финансовые операции не меняются. Это предотвращает доказанный порядок потери данных при ошибке подготовки; это не атомарная транзакция Docker и не резервная копия. Сбой Docker после успешного preflight остаётся возможным. Посторонние держатели томов оператор рассматривает отдельно, не удаляя их автоматически.

## Проверки

На прежнем `install.sh` из `3683fd5`: новые shell-регрессии **10 failed**. На исправленном коде: **29 passed**, включая 11 новых и существующие проверки port ownership, record cassettes и seed install. Docker, curl и STT в этих проверках заменены локальными исполняемыми fixtures; настоящий Docker и primary не использовались.

Проверяются ошибки config/build/pull/model/inspect до `down`, stopped foreign/one-off holders, порядок успешной подготовки, отсутствие pull для cached images, получение образа явно включённого optional profile и profile только из `.env`. Список активных сервисов берётся непосредственно из resolved Compose config, без повторного разбора `.env` или объединения profile-переменных; приоритет shell/CLI и `*` определяет сам Compose. Отдельная config-only проверка установленного Compose подтвердила выбор активных сервисов без обращения к Docker daemon. В ошибку не попадает содержимое resolved config.

`bash -n install.sh`, Ruff check и Ruff format проходят. Полные `make lint`, contracts и owners прошли на immutable source `76edc49e45455aca0f62e6fa5a537ee14f209188`. Полный `make test`: **4155 passed, 20 skipped** — unit 2378/19 skipped, integration 1018, scenarios 44/1 skipped, compliance 31, frontend 634 (85 файлов), bot 50. Исходники после прогона побайтно сохранены, собственный PostgreSQL остановлен.

Native preflight-only проверка на отдельном Compose project также прошла: собственный образ `FROM scratch`, optional cached PostgreSQL из `.env` profile, отсутствие pull cached images и отказ при собственном неработающем one-off держателе тома. Контейнер сохранился в состоянии `created`, его volume сохранён. `down`, reset и запуск приложений не выполнялись. Primary не использовался.

После полного прогона изменены только документация и уточняющий Python-комментарий о resolved volumes; AST helper совпадает с проверенным source. Это не новый полный local make финального head; полный CI финального head проверяется отдельно перед merge. Чистая Ubuntu VM и настоящий destructive reset этим пакетом не проверялись. Приватные RED/GREEN журналы находятся в `.runtime/install-reset-preflight-qa/` вне Git.

## Откат

Откат к предыдущему коду установщика не восстанавливает удалённые volumes. Нормальный повторный запуск выполняется без `--reset`; старый код с прежним порядком reset использовать для удаления данных не следует.
