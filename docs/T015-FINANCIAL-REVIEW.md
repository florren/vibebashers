# T-015: финансовые defaults — предложение для review

Статус: **нужно явное подтверждение человека до merge**. Этот документ описывает
отдельный финансовый commit после каталога коммуникаций `e31e6bb`; production,
существующий стенд и денежные действия не изменялись.
Основание approval — [AGENTS.md §5](../AGENTS.md): «Подтверждение человека нужно
только в трёх случаях: изменение контрактов, всё, что касается денег и HITL
(`refund_fee`, политики, лимиты), удаление или переименование файлов чужого слоя».
Этот commit затрагивает финансовый default и выбор ставки, поэтому требует review.

## Проверенные основания

[ТЗ §14.4](TZ.md) прямо задаёт default `misselling_case_cost_rub = 4050 × 1.0`
с пометкой о согласовании с бизнесом (§20.3 п.1). Там же `notification_gw`,
`promo_engine`, `antifraud`, `core_abs` и системы вне таблицы направлены на среднюю
ставку `bank_average = 4050`. Решение заказчика о ставках вне таблицы повторено
в §20.2 п.5. Приоритет определённого продукта сохраняется.

Контракт [schema.sql](../contracts/db/schema.sql), колонка
`economics_settings.misselling_case_cost_rub`, также содержит `DEFAULT 4050`.
[ADR-0007](adr/ADR-0007-dcltv-economics.md) фиксирует единственную формулу и
среднюю ставку 4050. Значение 25000 найдено в исходном seed
`c6a5247` от 22.10.2026; отдельного числового решения 25000 в просмотренных
ТЗ/ADR не найдено.

[ADR-0012](adr/ADR-0012-anonymous-handoff.md) и
[ADR-0013](adr/ADR-0013-financial-impact.md) от 29.10.2026 сохраняют настраиваемую
специальную стоимость мисселлинга и основную модель. Они не задают сумму 25000.
Предложение трактует это как сохранение механизма, а default возвращает к явному
ТЗ/DDL. **Эта трактовка требует подтверждения reviewer:** если «прежняя стоимость»
в ADR означала числовую фиксацию 25000, этот commit нельзя сливать без разрешения
противоречия. Демо-штраф 50000 из ADR-0013/0014 — отдельный показатель;
его и рабочие политики штрафов предложение не меняет.

## Точный diff

- `data/gifts.yaml`: только `misselling_case_cost_rub: 25000 → 4050`.
- `data/dcltv_rates.csv`: удалить `promo_engine` из `loyalty.maps_to.systems`
  и `notification_gw` из `notifications.maps_to.systems`; соответствующие
  `maps_to` становятся `{}`. Эти системы без определённого продукта/канала
  доходят до существующего `bank_average` fallback. Специальное правило
  ADR-0012 для неизвестного продукта по-прежнему выбирает среднюю даже при
  известном канале.

Все 30 исходных ставок и дополнительный существующий alias `notifications`
сохранены с прежними кодами, именами и точными Decimal суммами. Ставки
`loyalty = 373.005` и `notifications = 292.005` не меняются; исправляются их
привязки к системам. Формулы, product/system/channel приоритет, premium addon,
доли, retention coefficients, HITL, возвраты и лимиты подарков не изменены.

Практический эффект: system-only preview для `notification_gw` использует
4050 вместо 292.005, для `promo_engine` — 4050 вместо 373.005. Определённый
`deposit` по-прежнему использует 961 при любой из этих систем. Для одного
случая мисселлинга без premium addon базовая потенциальная стоимость после
загрузки нового default равна 4050; ручная настройка 7777 продолжает работать.

## Применение и откат

Commit не содержит миграции, автоматического reseed или пересчёта истории.
Существующая БД не меняется от checkout/merge. **Но текущий**
`scripts/seed/refs.py:seed_economics` при повторном seed делает upsert ставок,
`maps_to` и `misselling_case_cost_rub` из файлов: он перезапишет и ранее
настроенную вручную стоимость случая. Это прежнее поведение seed, которое
здесь не меняется. Решение о seed существующего стенда требует отдельного
явного разрешения и сохранения его текущих настроек.

Сохранённые `incident_economics` не мигрируются; последующие расчёты и явный
пересчёт после загрузки настроек используют новые значения. Автоматический
исторический backfill не выполнялся. Откат исходников — revert финансового
commit; для уже отдельно reseeded БД нужны сохранённые прежние настройки,
одного revert для восстановления данных недостаточно.

## Проверка

Адресные unit проверяют точные исходные суммы, финансовый default 4050,
реальный CSV fallback для пяти систем и неизменный product priority.
PostgreSQL regression на собственной `cx_t015_catalogs` проверяет реальные
seeded `maps_to`/settings, стоимость мисселлинга 4050 в вычисленном и сохранённом
результате и сохранение настраиваемого значения 7777. Тест не меняет HITL,
проводки или production и откатывает свои изменения transaction rollback.

mypy (242 source files), contracts (44 схемы / 161 путь), OpenAPI drift
(191/191) и `git diff --check` прошли. Полный CI и получение человеческого
подтверждения выполняет основной агент; этот документ не является approval.
