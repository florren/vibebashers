# #135: чистый старт с seed42

## Отчёт

После `bash ./install.sh --reset --seed 42` основной backend стал healthy и создал
`sim_state` до вызова seed. `preserve_existing` ошибочно считал эту строку признаком
заполненной БД и возвращал4. До восстановления:0 клиентов,0 продуктов,0 операций,
0 сигналов, отсутствовал seed_done. Запущенный пользователем World содержал пустой
список клиентов; flush_signals падал с Cannot choose from an empty sequence.

Минимальное исправление исключает служебный sim_state из признака существующего
банка. Клиенты или sim_runs без корректного seed_done по-прежнему останавливают
автоматический seed. Повторная установка заполненного банка остаётся read-only.

Целевая PostgreSQL-регрессия проходит чистую схему → Simulator.load_state →
seed --if-needed --seed42 → новый free-run →120 минут генерации. Проверяются200
клиентов, маркер seed42, ненулевые новые операции/сигналы/sim_events именно нового
запуска. Параллельно сохранены проверки повторной установки, незавершённого seed,
ошибок coverage и pg-tools:7 passed. LLM в этой регрессии не используется.

Рабочий стенд восстановлен без нового reset и без удаления: остановлен пустой run1,
сохранены снимок БД и старые файлы baseline, штатный seed lite/42 создал1000 клиентов,
4 продукта,10935 исторических операций и800 сигналов. Backend перезапущен для очистки
кэша пустого World, создан новый run3. Эти исторические счётчики сами по себе не
доказывают новую генерацию: отдельные счётчики активного run проверяются после Start.

Проверки lint/test/ownership и итоговые измерения рабочего запуска — в описании PR.
Контракты, схема, параметры генерации и денежные политики не менялись.
