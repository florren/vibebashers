# #142: неудачная попытка и сохранение профиля

## Что установлено на стенде

SIG-000802 / INC-000152: первый сохранённый план команды имел outcome=on_time
(01.11.2026 09:24:09 МСК), все шаги до close выполнены. Его ответ об устранении
соответствует фактически исполненному плану. Переключение общего профиля задним
числом не переписывает начатый план и отправленное уведомление.

SIG-000803 / INC-000153: план failed (09:26:05 МСК), выполнены take/rca/fix_decision/
progress_report. На ручном локальном времени следующий escalate_ack вызывал
ToolError: переход fix_proposed → escalated недопустим. Общий SLA-тик здесь не идёт,
в отличие от изолированного demo. В БД SIG803 не имел resolved: только ack_received;
GET Journey также возвращал только подтверждение приёма. AR20 оставался deferred.

## Исправление

TeamEmulator возвращает неудачную попытку из fix_proposed/fix_deployed/verifying
в in_progress перед штатной эскалацией. Глобальная FSM и денежные/HITL-политики
не меняются. Failed/no_work дают одно demo_unresolved, инцидент остаётся открытым.
Recovered сначала сообщает о задержке, затем после проверки даёт resolved.

Текст ru/en сообщает о дополнительном времени, продолжении работы и возвращении
с результатом без выдуманного срока и без заявления об устранении:

> Приносим извинения: проблему пока не удалось устранить. Нам потребуется больше
> времени для её решения. Мы продолжаем работу и вернёмся к вам с результатом.
> Ваше обращение остаётся открытым.

Выбор в списках — локальный черновик. Для ручного текста нужно «Сохранить профиль
обработки»; «Входной сценарий» относится только к отдельному demo-запуску. UI показывает
неприменённые параметры и отдельно сохранённый профиль. После успешного Save
синхронизируется подтверждённое сервером состояние; ошибка сохранения оставляет
черновик. Явное сохранение очищает старую ошибку исполнения, сохраняя паузу и run_id.
Уже начатые планы не пересоздаются. Кнопки сгруппированы и не разъезжаются при переносе.

## Проверка

Точный снимок SIG803 восстановлен в отдельной БД: legal transitions
fix_proposed→in_progress→escalated, одно правильное уведомление,0 resolved,
SIG802 и его старый ответ сохранены. Часы не двигались. Повторные циклы не дублируют
уведомления; явное сохранение failed-профиля очищает ошибку и сохраняет paused.

На отдельной копии проведён синтетический PDF-кейс с реальным GigaChat:
SIG804→INC154,14.83s,11/11 LLM-вызовов source=live,два accept/operator:live.
Шаги take→rca→fix_decision→progress_report→escalate_ack,статус escalated,
AR deferred,одно сообщение о продолжении работ,0 resolved,часы на паузе.
Идентификаторы этой проверки относятся к копии,а не к основному стенду.

Локальные обязательные проверки: make lint (ruff/format,mypy240,drift0),
make test (697 unit passed/18 skipped,6 integration passed/199 skipped без БД,
2 scenario passed/42 skipped). Все пять исходов отдельно проверены в manual/paused
контуре без общего SLA-тика. Frontend:lint/typecheck,139 тестов и production build.
Локальный Node26 запускает vitest с NODE_OPTIONS=--no-experimental-webstorage,
чтобы использовался jsdom localStorage; CI использует Node22.

В существующем compliance-тесте обнаружено окно гонки: анализ мог завершиться между
чтением алерта тестовым перехватчиком и чтением настоящего employees. Добавлен
барьер до появления готового алерта; все проверки ручного/автоматического решения
и идемпотентности сохранены. Продуктовая логика комплаенса не изменялась.
Итог расширенных PostgreSQL-проверок,CI и установки — в PR.
