# Холодный GigaChat — 31.10.2026

[Решение](../../adr/ADR-0022-gigachat-cold-start-rotation.md).
Тот же [набор 20 текстов](../gigachat-normalize-hitl-2026-10-31/cases.json), штатные
normalization prompt/schema и выбранные профили стенда. Без записи сигналов/БД.

## Причина и сравнительные проверки

- Повтор исходной версии: [18/20](before.json). [Transport trace первого отказа](before-transport.json)
  локализует ожидание в TLS OAuth до отправки HTTP, затем повторный выбор того же
  ключа на Pro. Предыдущий прогон PR #112 дал 19/20, это другой запуск.
- Ротация и транспортный дедлайн: [20/20](rotation-only.json) при одном холодном
  старте и дальнейшем переиспользовании клиента. Но [11/20](raw-cold.json), когда
  каждый текст создаёт новый клиент без подготовки. Одной ротации недостаточно.
- Один проход подготовки: [17/20](single-pass-prepare.json), все три отказа — при
  prepared=false. Поэтому добавлен второй проход в том же 12-секундном дедлайне.
- [TCP/MSS сравнение](transport-comparison.json): 20 холодных соединений на каждый
  endpoint и режим, порядок чередуется. И default, и MSS 1200 дали OAuth 20/20,
  API 19/20 (HTTP 405/403 ожидаемы: запросы без авторизации). Улучшения нет,
  MSS/MTU и TLS-протоколы не менялись. Измерения не определяют сетевую причину.

## Финальный прогон: 20 независимых холодных запусков

```sh
python scripts/bench_normalization_timeouts.py \
  --dataset docs/benchmarks/gigachat-normalize-hitl-2026-10-31/cases.json \
  --output results.json --limits 10 --cold-each --prepare
```

Новый HTTP-клиент и пустой OAuth-кэш для каждого текста. prepare повторяет фазу
startup backend; генерация до нормализации не выполняется. Время подготовки
не скрывается: initialization_ms + elapsed_ms = cold_total_ms.

[Финальные результаты](final-cold.json): **20/20 подготовлены, 20/20 валидных live-ответов**,
11 Lightning, 8 Pro, 1 Ultra, без replay/mock. [15 транспортных ошибок ключей](final-key-errors.json)
не скрыты, обработаны ротацией/вторым проходом. Это не 15 неуспешных кейсов.

- Подготовка: p95 8350 мс, максимум 8946 мс (лимит 12 с).
- Нормализация: p95 6332 мс, максимум 9918 мс (лимит 10 с).
- Холодный запуск вместе с нормализацией: p95 13505 мс, максимум **14524 мс**.
- Первый кейс: подготовка 3496 мс, нормализация 1249 мс, всего 4745 мс.

10 секунд — бюджет обработки после готовности backend, а не обещание полного
холодного запуска за 10 секунд. При недоступной сети подготовка честно сообщает
ok=false, а runtime сохраняет штатный replay/mock. Эти последовательные замеры
текущего стенда не гарантируют результат при любой нагрузке/отказе провайдера.
