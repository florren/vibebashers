# Проверка demo-исполнения 31.10.2026

Проверка проводилась на отдельных PostgreSQL 16 базах и тестовом `127.0.0.1:8011`. База рабочего стенда `:8000` для тестов не использовалась.

## Живой GigaChat

Сценарий `deposit_promo_rate`, профиль команды `on_time`, два клиентских сигнала. Полный цикл занял **37,23 с**. Инцидент `INC-000151` закрыт, `sla_breached=false`. Все пять артефактов команды сформированы `GigaChat-3-Pro:32.4.30.3`, `source=live`. Уведомления клиентам: два `ack_received`, два `resolved`, два штатных предложения подарка.

На отдельных начальных шагах сработала штатная подстраховка после timeout/невалидного JSON. Поэтому результат не трактуется как «все шаги live». Проверка не подтверждает целевой бюджет 4,5 с из приложенного ТЗ и не меняет стоимость вызовов из настроек тарифов.

## Воспроизводимость

Backend: Python из `uv`-окружения проекта; PostgreSQL 16 и совместимые `pg_dump`/`pg_restore` 16. Тестовые процессы запускаются с отдельным `DATABASE_URL_TEST`, `APP_ENV=test`, `LLM_PROVIDER=mock` и пустым `ENV_FILE`, чтобы рабочие LLM-ключи не попадали в фикстуры benchmark.

Frontend: CI использует Node 22. На локальном Node 26 для Vitest отключён экспериментальный глобальный Web Storage (`NODE_OPTIONS=--no-experimental-webstorage`), чтобы jsdom предоставлял свой `localStorage`. Настройки приложения и проверки не ослаблялись.

Финальный целевой прогон текущего кода: **30 passed**, coverage новых `app/demo` и `api/demo_execution` — **88%** (API 96%, исполнитель 84%, LLM-ответы 95%). Проверены пять исходов, ручной приоритет, автоматические решения, комплаенс без явной жалобы, уведомления в исходном канале и 20 параллельных входов. Coverage tooling установлен только в `/tmp`, зависимости проекта не менялись.

Полный локальный `make test`: 658 unit passed / 18 skipped, 153 integration passed / 2 skipped, 42 scenario passed / 2 skipped. Дополнительная регрессия обновления существующей БД без seed входит в итоговые 30 целевых тестов.

Дополнительные финальные регрессии: три промежуточных SLA-отчёта длинного инцидента опубликованы до своих исходных due_sim; пропусков отчётов нет. Детерминированно воспроизведён переход анализа транскрипта в done до ответа руководителя: процесс ждёт решения и отправляет конечный ответ как при demo-, так и при ручном подтверждении. Полный unit-набор после этих исправлений: 660 passed / 18 skipped.
