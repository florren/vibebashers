# T-266 — продукты финансового эффекта

30.10.2026, GitHub #93. Контракты OpenAPI 1.5.4, ADR-0014 (дополнение о фильтре).

## Фильтр и границы

Один product_mode/product_codes применяется сервером к основной модели, ручным сценариям, top product, графику, реестру и обоим контурам. all включает кейсы без продукта; include с пустым списком означает ни одного, exclude с пустым списком — все. Все продукты отмечает весь справочник. Режим исключения сохраняет отметки. Неизвестные коды дают 422, значения передаются SQL параметрами.

Первый кейс клиента и последняя версия сделки выбираются по всему запуску до фильтра продукта/даты. Поэтому риск первого кейса по дебетовой карте не появляется повторно на более позднем кейсе по вкладу. Возвраты учитываются по всем отобранным кейсам. Рабочие P и штраф сохраняют null без отдельно допущенных данных/согласований.

## Браузерный regression

report.json и скриншоты получены на отдельном preview FastAPI/PostgreSQL, lite baseline с 200 синтетическими клиентами, настоящий mock QR-граф и синтетический дополнительный кейс того же клиента по вкладу. API не перехватывается. Для каждого ru/en × light/dark проверены include с пустым списком, один продукт, exclude, пустой exclude и Все; суммы UI сверены с API total/assessment, case_count совпадает с реестром, рабочий контур остаётся unknown. Проверена ширина 390 px.

Проверенный пример: все — 2 кейса, основная модель 43.55 ₽, возвраты 460 ₽, demo risk 194.85 ₽. Только вклад — 1 кейс, 20.63 ₽, возврат 10 ₽, demo risk 0 ₽ (первый риск клиента относится к карте). Всё кроме вклада — 1 кейс, 22.92 ₽, возврат 450 ₽, demo risk 194.85 ₽. Это синтетическая проверка механики, не банковский результат и не оценка реального качества NLP.

Воспроизведение на подготовленном paused-стенде с решёнными кейсами: `CX_BASE_URL=http://localhost:8000 CHROME_EXECUTABLE=/path/to/chrome CX_SCREENSHOT_DIR=/tmp/finance-products node docs/benchmarks/finance-products-2026-10-30/capture.mjs`.
