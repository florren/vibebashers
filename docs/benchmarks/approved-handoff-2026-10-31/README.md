# #133: передача анонимного инцидента после HITL

## Отчёт

При проверке рабочей публичной очереди после #132 девять старых ожидающих сигналов
завершились, но SIG-105816/INC-001355 и SIG-105823/INC-001389 остались заблокированы.
Их решения 1860/1887 имели accept, агенты 2082/2115 — deferred/awaiting_team,
а статус инцидента оставался awaiting_human. Повторный route обновлял поля команды,
сохраняя старый статус. TeamEmulator намеренно не исполняет awaiting_human.

Добавлен внутренний helper resume_approved_incident: блокировка строки, проверка последнего сохранённого
accept/modify для этого инцидента и отсутствия других нерешённых HITL,
переход в routed через штатный update_incident с историей. Новое имя инструмента
в публичный контракт не добавляется. Act вызывает helper
после принятого маршрута. Reject/delegate не запускают этот переход.
Повторное применение к уже переданному инциденту не меняет статус и историю.

Регрессии используют анонимный landing-вход, реальное правило low_confidence
со строгим тестовым порогом 0.99, существующий checkpoint и resume_after_human.
Проверяются отсутствие перехода без согласования, другое pending-решение,
передача после последнего согласования, идемпотентность и полная цепочка до
одного resolved/sent без запуска банковских часов. Внешних сервисов в тестах нет.

Схема, контракты, условия денежных действий и обязательность HITL не меняются.
Для двух выбранных исторических инцидентов применяется тот же защищённый
инструмент с идентификатором ранее согласованного agent_run; снимок до изменения
сохраняется в отдельном операторском agent_run/agent_steps и incident_history.
Решения человека и старые followup не удаляются; продолжение команды штатное.

Откат кода — образ до #133. Откат выбранных данных возможен по снимку и истории;
отправленные конечные сообщения сохраняются. Не следует восстанавливать всю БД
поверх новых обращений ради отката двух выбранных записей.

Локальные проверки: make lint (ruff, формат, mypy239 файлов, drift0), make test
(676 unit passed/18 skipped;6 integration passed/184 skipped без тестовой БД;
2 scenario passed/42 skipped), contracts_check44 схемы/160 путей, owners L1/L3
с --allow-cross. На отдельной PostgreSQL16:14 passed (новые handoff-регрессии,
существующие HITL-проверки и полная публичная цепочка). Скриншоты не требуются:
интерфейс не менялся. Результаты CI и применения к выбранным старым записям — в PR.
