# ADR-0015 — Непрерывность сигнала и информации оператора

Статус: принято по запросу заказчика, 30.10.2026; T-267 / GitHub #95.

## Проверенные причины

SIG-088489 сохранён в запуске SR-0009 со статусом deferred. Он связан с INC-000826 (тип tariff_terms) и ESC-000085; repeat_negative — причина HD-001351 и эскалации. Решение HD пустое, AR-001549 deferred, wait_human отсутствует. Шаги normalize/classify/decide сохранены от реального GigaChat (Lightning/Ultra). Это non-blocking эскалация, а не решение оператора или исчезновение записи.

Прежний поиск сигналов проверял только text; лента ограничивалась текущим запуском и 100 строками без догрузки. HITL показывал первые 50 записей без поиска/пагинации; run_id API игнорировался. Интерфейс не различал эскалацию без паузы графа и настоящий wait_human; resume без checkpoint ничего не делал. При исчезновении строки из очереди терялись выбранная карточка и видимый ввод.

## Поиск и происхождение

В операторских вкладках Signals/HITL по умолчанию выбраны все запуски, доступно явное ограничение текущим. Метрики/симулятор сохраняют свою изоляцию. GET signals сохраняет совместимый default current; UI передаёт all. Все 11 статусов из контракта доступны; отсутствие status-фильтра включает любой статус. Оба списка имеют cursor-пагинацию и догрузку.

q принимает текст и коды общего реестра: SIG/INC/HD/AR/ESC/TSK/SR/CL/POST/TR/AS/EMP/VSP/CSI/NTF/FUP/LED, RULE и коды ошибок, также UUID/синтетический tracking ref. Значения параметризованы, %/_ экранируются. По существующему корневому объекту строятся SQL-наборы связанных сигналов и инцидентов; источники и продукты не выдумываются. Поиск SIG не расширяется через общего клиента/сотрудника на посторонние дела; CL/EMP/VSP/SR выбирают такую область только как явный корень. Связи incident_signals проверяются в пределах одного запуска. Ограничения выбранного run_id применяются к результатам.

Поиск HITL включает обработанные запросы, даже если флаг истории выключен. Без q очередь содержит открытые и автоматически продолженные запросы; include_decided добавляет обработанные человеком. В карточке показаны SIG → связанные INC, HD, ESC и SR, состояние графа; из SIG/INC есть ссылка в HITL по коду. Даже при отсутствии HD поиск показывает связанные коды отдельным блоком (до 100, с явной пометкой усечения). Исходные записи сохраняются, инцидент связывается с сигналом.

## Продолжение и ввод

can_resume=true только для открытого HD, agent_run.outcome=awaiting_human и сохранённого wait_human с human_decision_id именно этого HD; proposal.kind=escalation исключён. Лишь такой запрос запускает resume после формального решения. Non-blocking эскалацию можно отметить обработанной, без повторения графа; устаревшие modify/delegate отклоняются с 409 и указанием журнала. Во время формирования checkpoint решение временно запрещено, ввод информации доступен. Решение фиксируется под FOR UPDATE; timeout fallback возобновляет граф только если conditional UPDATE действительно изменил строку.

Выбранная карточка запрашивается отдельно по id и сохраняется после выхода из списка. Черновик комментария общий у формального ответа и журнала, поэтому автоматическое продолжение не уничтожает набранный текст. Автоматический timeout показывается как автоматическое действие, а не решение человека. Политика таймаута и её безопасное acknowledge без подарка сохранены.

## Журнал информации

Миграция 0009 добавляет hitl_feedback с FK на HD, текстом, меткой оператора, recorded_sim/recorded_at и уникальным ключом повтора. GET/POST /api/hitl/{id}/feedback доступны в любом состоянии исходного HD; история пагинируется. Повтор идентичного ключа возвращает ту же запись, другое содержимое — 409. UPDATE запрещён; API изменения/удаления нет. SQL-администратор и удаление родительского запуска остаются эксплуатационными полномочиями MVP.

Журнал сохраняет сведения и их связь с SIG/INC через HD, не меняет прежнюю decision/decided_by, не возобновляет старый граф и не создаёт денежных операций. Операторские сведения доступны в карточке HITL и через ссылки из SIG/INC; они не объявляются новым одобрением старого предложения и автоматически не исполняются. Метка оператора не является аутентификацией (MVP сохраняет прежнюю модель доступа).

recorded_at — реальное время получения; recorded_sim — текущие часы стенда, в том числе при вводе в историю прошлого запуска. Это не подстановка сведений в старое решение. Поиск и GET не вызывают LLM.

## Проверка и откат

Regression: исходная цепочка без записи решения за пользователя; все статусы/прошлый запуск; все типы кодов; пагинация; отсутствие расширения через общего клиента; ответ после timeout/ручного решения; idempotency; неизменность исходного решения, графа и проводок; сохранение карточки/черновика. UI ru/en, обе темы и мобильная ширина. Откат приложения сохраняет аддитивную таблицу/историю, downgrade 0009 не удаляет сведения. До применения сохраняется предыдущий image и локальный backup БД; baseline reset не требуется.
