# ADR-0019 — Синтетические источники и восстановление в ожидании

Дата: 30.10.2026. Статус: принят. T-272/T-273/T-274, GitHub #103/#104/#105.
Cross-layer и точечная правка первого live-входа согласованы пользователем.

## Причина

Старый polling_worker независимо от sim_state.running вызывал заглушку _mock_batch,
игнорировавшую URL и corpus. Сообщения на реальном таймере попадали в текущий,
в том числе исторический, запуск. После рестарта _recover запускал по ним агента.
Доказательства и команды: [измерения](../benchmarks/idle-generation/README.md).

## Решение

Автоматическая синтетика остаётся в World и использует SimClock/SimRng. Второй
автономный таймер для неё не нужен. Встроенные mock_social_polling/review_portal_feed
считаются синтетическими даже при старой конфигурации enabled=true; фоновый воркер
их пропускает. Новые defaults выключены. Для mock есть явная команда «Опросить сейчас»
только при running=true, небазовом текущем запуске со status=running. Корпус встроен,
batch ограничен, cursor и сим-время сохраняются; пауза блокирует эту команду.
Это уточнение исключения для встроенного демо-адаптера из AGENTS §6.10/ТЗ 3.7,
а не выключение приёмного слоя. Настоящий URL-адаптер остаётся незавершённым:
возвращает last_error, не подменяет сетевой ответ выдуманными сообщениями.

Точная legacy-сигнатура origin=polling + nick=mock_feed + префикс заглушки
исключается из автоматических LISTEN/recovery, followups и истечения HITL.
Записи и решения сохраняются. Явные новые mock-пакеты помечены synthetic_mode=manual.
Исторические origin=sim в baseline не ставятся в очередь recovery/LISTEN; реальные
origin=api/jury/review_portal и настоящие незавершённые обращения восстанавливаются.
TwinService и ABS backfill не изменены: источник нежелательной генерации не в них.

Если current_run_id=NULL, явный HTTP-вход через общий run_context вызывает существующий
ensure_live_run. Транзакционная блокировка sim_state гарантирует один live-run при
конкурентных запросах; dict_row HTTP-соединений поддержан локальными tuple-курсорами.
Simulator синхронизирует указатель под своим lock, чтобы shutdown не затёр его.
Часы/World/тик не запускаются, существующие baseline/free/scenario сохраняются.
Это изменение отдельно согласовано пользователем; публичные схемы не менялись.

## Историческое покрытие

repair_csi.py по умолчанию показывает план, --apply в одной транзакции добавляет
только отсутствующие CSI-пары завершённого seed baseline через normalizer. Новые
исторические записи сразу closed; старые сигналы/решения/проводки не переписываются.
Меняется только coverage и штатные CSI/provenance/audit-записи; повтор — no-op.
Пробелы вне CSI/SLA, неподходящий baseline и ошибка вставки отменяют операцию.
Старый baseline.dump не заменяется живым состоянием. После восстановления именно
старого архива добавочный ремонт нужно повторить.

## Проверка и откат

Регрессии: idle/pause во всех профилях; manual start/pause/resume; восстановление
настоящих обращений и исключение legacy; первый live HTTP + конкурентные запросы,
синхронизация памяти/shutdown; fixed-seed повтор из снимка; CSI dry-run/атомарность/
идемпотентность и неизменность прежних данных. Полный make lint && make test.
Перед обновлением стенда — приватный pg_dump и тег прежнего image. Схема не меняется.
Откат кода — прежний image; для исключения старого дефекта оставить только два mock
источника disabled. Добавленные CSI можно сохранить: они совместимы с прежним кодом.
