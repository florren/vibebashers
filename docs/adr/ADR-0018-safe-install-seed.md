# ADR-0018 — seed при установке и инструменты baseline

Принято 30.10.2026, T-270 / GitHub #100. Повторный install на живом стенде не должен менять данные или подменять baseline текущей историей.

## Решение

`install.sh` вызывает seed с `--if-needed`. Сначала проверяются доступность pg_dump/pg_restore и совпадение их major с сервером. Для Docker закреплены Python 3.12 / Debian bookworm и postgresql-client-16 из официального подписанного PGDG; сам PostgreSQL остаётся 16. Источник настройки репозитория: https://www.postgresql.org/download/linux/debian/. Одна major для dump/restore/server исключает неопределённость обратной совместимости: https://www.postgresql.org/docs/16/app-pgdump.html.

Если бизнес-данные уже существуют, seed только читает seed_done, матрицу старого baseline и состояние файлов baseline. Справочники, настройки, клиентские записи, решения, время, запуски и архивы не перезаписываются. Недостаточное покрытие существующей истории показывается предупреждением с отсутствующими комбинациями; оно не выдаётся за успешную проверку coverage и не является поводом пересоздавать историю. Отсутствующий seed_done или потерянный baseline-run означают незавершённую инициализацию (код 4), без автоматической очистки. Несовпадение запрошенного профиля отображается, существующий профиль сохраняется.

На пустой БД обязательны первоначальный seed, coverage (код 2 при провале) и создание baseline (код 3 при ошибке tooling/dump). Маркер успешного seed не сохраняется при провале обязательного baseline. Установщик прекращает работу при ненулевом результате и сообщает реальную причину вместо старого «сид ещё не реализован». `--if-needed` несовместим с --refs-only/--reset-history. Ручные команды обновления справочников и явно запрошенный reset сохраняют отдельную семантику.

Отсутствующий baseline у старого стенда показывается явно. Повторная установка не создаёт его из текущего живого состояния: так в будущий reset не попадут чужие запуски/операторские решения. Это не замена резервной копии; перед обновлением стенда делается отдельный приватный backup.

## Проверка и откат

Regression сравнивает все таблицы и байты baseline до/после --if-needed, в том числе при новых каналах, другом профиле и seed. Проверяются exit 2/3/4, отсутствие tooling до записи, частично инициализированная БД. Docker проверяется с PostgreSQL 16 и настоящими pg_dump/pg_restore. Изменений схемы БД нет; откат — предыдущий image, без reset тома.

CI tests закреплён на Ubuntu 24.04, явно устанавливает postgresql-client-16 и добавляет его bin в PATH перед pytest. Таким образом baseline roundtrip проверяется против PostgreSQL 16 service, а не случайно пропускается или использует другую major предустановленного клиента runner.
