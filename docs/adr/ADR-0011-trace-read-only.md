# ADR-0011 — Модель следа и пути обращения — только чтение

| Поле | Значение |
|---|---|
| Статус | принят |
| Дата | 27.10.2026 |
| Решение принял | техлид (Денис); подготовил архитектор |
| Связанные разделы | ТЗ 27, 28; AGENTS.md правило 19, §6.11; карточки T-223–T-235 |

## Контекст
Для демонстрации нужны экран «Путь обращения» (цикл от сигнала до сообщения клиенту) и «Поиск и след» (до / объект / после). Соблазн — завести отдельное хранилище «истории» или дописывать недостающие шаги при показе.

## Решение
Единый сборщик `app/trace`: детерминированный каузальный обход уже записанных данных (`agent_steps`, `tool_calls`, `sim_events`, `notifications`, `external_replies`, `ledger_entries`, `human_decisions`, `followups`, `escalations`) с фазами `before|subject|after`, итогом, ожидаемыми шагами (`pending`) и свёрткой веера (группы от 8 элементов). Сборщик не вызывает LLM, не пишет в БД и не кэширует состояние вне запроса; модель «Путь» (8 стадий, две дорожки) — проекция того же следа. Каждому трассируемому объекту добавлен `public_id` (миграция 0004). Правило 19 AGENTS.md.

## Последствия
Если на экране чего-то не хватает, исправляется источник (узел агента пишет шаг, симулятор пишет событие), а не сборщик. Бюджет `GET /api/trace` p95 ≤ 300 мс при следе до 200 событий; изоляция запусков и маскирование ПДн — обязательны.
