# ADR-0020 — Автоматический CSI-ремонт при восстановлении baseline

Дата: 30.10.2026. Статус: принят. T-275, GitHub #107.

## Контекст

T-272 предоставил атомарный добавочный repair_csi.py, но после восстановления
совместимого архива 440/480 требовался ручной запуск. Нужно гарантировать готовый
baseline до baseline_restore_finished и старта нового сценария, сохраняя детерминизм.

## Решение

Общий baseline.restore проверяет наличие CLI до восстановления, возвращает sim_runs
и каталог runs/, фиксирует строки запусков, затем выполняет существующий CLI
`--apply --json` в отдельном процессе. Его запуск вынесен из event loop через
asyncio.to_thread. Отдельный процесс не меняет глобальную конфигурацию structlog
приложения при импорте seed-модулей; нет второй реализации алгоритма ремонта.

CLI сохраняет прежний режим вывода и получает необязательный JSON-режим для
автоматизации. Родитель проверяет exit code и результат after/total/added;
ошибка или некорректный ответ не превращаются в finished и не стартуют новый запуск.
Причина ожидаемой ошибки видна через существующий HTTP 409. Схемы API/БД не меняются.

Async dump и restore получают DSN из переданного psycopg-соединения. info.dsn
исключает пароль, поэтому аутентификация восстанавливается через info.password и
make_conninfo. CLI получает DSN окружением, не argv. Различие DATABASE_URL_TEST и
DATABASE_URL больше не направляет подоперации в постороннюю БД.

Сам repair не изменён: advisory lock, одна транзакция, только отсутствующие пары CSI
завершённого исторического seed baseline, normalizer, historical/closed, без агента
и денег. При полном покрытии — no-op. После повторного restore старого снимка
восстановленная БД снова содержит ровно 40 CSI, а не накапливает 40 за каждый цикл.
Архив/метаданные/контрольная сумма не перезаписываются; часы/RNG ремонт не трогает.

## Границы и ошибки

Ремонт является атомарным, но вся последовательность pg_restore + восстановление
sim_runs + ремонт не является одной транзакцией. При отказе CSI остаётся восстановленная
БД без частично добавленных CSI; finished и старт сценария заблокированы. Архив остаётся
пригодным для повторной попытки. Пробелы вне CSI/SLA требуют исправления причины.

По отдельному выбору пользователя совместимость конкретного файла стенда вынесена
в T-276/#108: источник PG16.15, writer pg_dump18.6, custom format1.16, старая схема.
Установленный pg_restore16 не читает его header. Авто-CSI не исправляет форматы или
миграции; нельзя объявлять этот конкретный файл проверенным новым restore.
Рабочую БД для проверки восстановления не сбрасываем.

## Проверка и откат

Настоящий dump/restore совместимого неполного и полного архивов, повтор restore и
повтор repair, сравнение прежних данных всех таблиц, решений/ledger/времени/RNG,
байтов архивов, JSON-протокол, событие finished только после покрытия 480/480,
отказ без finished/start и неправильный глобальный DATABASE_URL. PG16 проверяется
на изолированной БД. Откат кода не требует миграции; исторические CSI совместимы.
