# ADR-0008 — Поиск на PostgreSQL: tsvector и расширение pg_trgm вместо Elasticsearch

## Контекст
ЕТЗ предлагает Elasticsearch для поиска по сигналам; стек зафиксирован без внешних сервисов, а объём данных демо (≤ 20 000 клиентов, десятки тысяч сигналов) не требует отдельного поискового движка. Нужны поиск по идентификаторам, подсказкам клиента и тексту с опечатками.

## Решение
Универсальный поиск `app/search` на PostgreSQL: точные идентификаторы по `public_id`, полнотекстовый поиск `tsvector('russian')` с GIN-индексами по `signals.text`, `incidents.title`, `external_posts.text`, нечёткий поиск — расширение `pg_trgm` (входит в поставку PostgreSQL, лицензия PostgreSQL). `CREATE EXTENSION IF NOT EXISTS pg_trgm` — в идемпотентной миграции 0004 (карточка T-223, `contract-change`). Redis и NestJS не добавляются.

## Последствия
Поиск соблюдает изоляцию запусков и маскирование ПДн (правило 19). Бюджет p95 ≤ 300 мс на профиле demo проверяется тестом. Образ PostgreSQL 16 уже содержит `pg_trgm`, дополнительных пакетов не требуется.
