# ADR-0027: интерактивный Journey и автономность принятых решений

Статус: принято по требованию независимой ручной обработки, 09.11.2026.

## Причины

Ручной Journey создаёт non-current live run, однако ingest, NOTIFY и recovery
помещали его в общую очередь четырёх фоновых исполнителей. При нагрузке World
новый сигнал оставался без AgentRun. После переоткрытия страницы поиск latest
ограничивался current и возвращал 404 для собственного non-current кейса.

После baseline reset архивные sim_runs сохраняются, хотя World возвращается
к началу. Сравнение их метаданных с новым глобальным временем ошибочно
блокировало общие метрики и тем самым страницу карты «Все запуски».

Автономность считала только закрытые проходы, теряя автономные deferred.
Дополнительный запрет любого critical противоречил ТЗ 9.3: для critical требуется
эскалация поверх маршрутизации. Уведомление руководителю также ошибочно ставило
needed_human, хотя граф продолжал исполнение без подтверждения.
История повторов также объединяла разные сбои одного широкого signal_type и
независимые запуски клиента, создавая лишние repeat_3plus.

## Решение

- Journey использует существующий interactive semaphore через все три entry
  paths и recovery checkpoint. Rate limits, provider chain, Graph/AgentRun
  ownership и maintenance admission сохраняются. World не запускается и не
  ускоряется отправкой ручного обращения.
- Без явно выбранного run ручной latest ищется в all; explicit scope сохраняется,
  а latest sim/feed остаётся current. Выбор закреплённого ref не меняется.
- Temporal guard использует finished_sim завершённого архива и подтверждённые
  факты собственного Journey. Неархивный World и его observed receipts
  по-прежнему проверяются против SimClock; некорректное будущее даёт 409.
- Автономность отражает записанные решения, включая deferred без человека.
  Ошибки и обязательный HITL не считаются автономными, pending LLM не считается
  решением. История и старые needed_human не переписываются ради процента.
- Critical продолжает маршрут с эскалацией. Юридические, fraud, Ultra VIP,
  повторные, партнёрские и остальные обязательные политики остаются. Notice
  не меняет needed_human и не может заменить или очистить настоящий approval.
- Repeat-HITL сохраняет порог 3. Новый контекст читает current + baseline, затем
  после classify считает точный SQL COUNT за 14 дней по одинаковой известной
  причине. Данные других запусков и иные tech_fault не считаются повтором.
  Preview 20 строк не ограничивает COUNT. Неопределённая причина не выдаётся за
  доказанный повтор; прежние checkpoints продолжают использовать свой контекст.
  Служебная версия контекста исключена из model input, поэтому не меняет
  replay identity. Кассеты не переписываются и не rekey-ятся.

## Проверка и внедрение

Регрессии используют настоящий Graph и PostgreSQL с занятым World semaphore,
потерянным NOTIFY, отдельным case clock и неизменным глобальным состоянием.
Отдельно проверяются архив после reset, сохранение future fence, честные 7/10
решений при двух pending, а также notice рядом с обязательным подтверждением.
Полный набор, браузер и реальный поток GigaChat проверяются перед завершением.

Постоянных таблиц, миграций, новых зависимостей и ручных служебных объектов нет.
Существующий новый Journey подхватывается штатным recovery без пересоздания
сигнала. Обновление не выполняет reset и сохраняет текущий запуск World.
Rollback: прежний образ приложения; схема БД и история не меняются.
