# ADR-0017 — изолированный анонимный чат и туннель

Принято 30.10.2026 по прямому запросу заказчика, T-269 / GitHub #98. Внешний туннель Tuna явно разрешён заказчиком; это публикация демонстрационной формы, не новая банковская интеграция.

## Граница публичного доступа

Отдельная Vite-сборка personal.html/dist-personal и FastAPI app.public_chat работают на loopback:9999 в сервисе personal. Нет операторской оболочки, навигации, Swagger, WebSocket управления, settings/finance/HITL/engine API или SPA fallback для неизвестных путей. Разрешены только personal/session/messages/reset/health, локальная диктовка и статические файлы этой сборки. На 8000 сохраняется операторский интерфейс, он не является целью туннеля. Публичный контейнер не получает LLM-ключи или Tuna-ключ и не монтирует .env.

Сообщения принимаются как landing без client_id и обязательных контактов через единый normalizer. Продукт/регион/город проверяются по справочникам. Источник и channel_subtype — ui_pers_demo, meta.tags содержит тот же тег; Signals имеет явный фильтр. Каждый следующий текст — новый связанный SIG с собственным стабильным ключом запроса. История своего разговора (до 20 прошлых сообщений/ответов в контексте) доступна агенту, обычные правила анонимного обслуживания не обходятся.

Приём возвращает 202, не выдуманный ответ агента. Чат показывает только собственные sent/delivered notifications типа client. Операторские заметки, чужие сессии, задачи, ключи и внутренние инструкции в публичную историю не попадают. Публичные обращения имеют два ограниченных интерактивных слота и устойчивый опрос signals, чтобы не ждать восстановления старого backlog или потерянного NOTIFY; исполняется тот же process_signal. Стартовое восстановление не помечает новые активные прогоны прерванными.

## Сессия и пассивные защиты

Случайная HttpOnly/SameSite=Strict cookie, Secure на HTTPS; в PostgreSQL хранится только SHA-256 токена, срок сессии 24 часа. HMAC формы связан с cookie и APP_SECRET. Same-origin проверяется для записей; CSRF не заменяет ограничения частоты. Для повтора используются UUID + hash нормализованного payload: прежний запрос не создаёт второй сигнал, другое содержимое с тем же ключом даёт 409.

Без CAPTCHA и дополнительного задания пользователю: honeypot, минимум 2 с от открытия формы/предыдущей отправки, максимум 5 сообщений/мин на сессию, 60 сообщений/мин суммарно, 200 новых сессий/час. Слишком ранняя отправка автоматически ожидает Retry-After, текст не теряется. Это ограничения злоупотреблений и эвристика, не доказательство того, что посетитель человек. До 200 сообщений в разговоре, затем предлагается новый чат; история не удаляется.

JSON ограничен 32 КиБ до полного чтения. Диктовка — локальный Vosk, до 30 с PCM16 16 кГц mono, ограничение тела/формата, один одновременный recognizer и 10 попыток/мин. Через публичный вход нельзя выбрать облачного провайдера/тестовый asset. CSP, запрет фреймов, nosniff, no-referrer и no-store ограничивают возможности страницы; blob разрешён для AudioWorklet. React выводит обращения как текст. Таймер/лимиты не требуют действий, кроме обычного ввода; доступ к микрофону разрешается стандартным диалогом браузера.

## Запуск и Tuna

install.sh готовит штатную малую Vosk-модель и запускает backend + personal, ждёт health:9999, затем scripts/tuna_tunnel.py читает ключ как данные из .env. Предпочтителен TUNA_API_KEY с tunnels:connect; TUNA_TOKEN поддержан для совместимости. Ключ передаётся только через окружение CLI, не argv, HTML, API или tracked-файлы. TUNA_ENABLED=0/--offline останавливают только собственный управляемый туннель. --no-stt пропускает подготовку модели; уже установленная модель остаётся доступной.

Команда заказчика: tuna http 9999 --subdomain=royal-penguin-6552 --rate-limit=10 --https-redirect --inspect=false. Инспектор выключен. Для headless используются TUNA_TUI=0/TUNA_NO_PROMPT=1. Повторный запуск проверяет pid/start-time/argv и не плодит процессы; смена ключа перезапускает только свой процесс. Приватный .cx/personal-tunnel имеет 0700, log/state — 0600. Адрес берётся из структурированного Forwarding CLI, включая новую зону tuna.free для Free; hostname/HTTPS проверяются. Успех объявляется только после проверки HTTPS-страницы, а не по факту существования PID. TLS verification не отключается.

Внешний CLI Tuna уже установлен системно, в проект не добавляются npm/Python-пакеты или vendor-бинарники. Права поддомена/ключа и доступность Tuna проверяются фактическим запуском; при ошибке локальная страница работает, installer явно сообщает о неготовности туннеля.

Официальные сведения: [переменные окружения](https://tuna.am/en/docs/guides/environment-variables/), [HTTP CLI и API key](https://tuna.am/en/docs/tunnels/http/), [установка и совместимость токенов](https://tuna.am/en/docs/guides/install/install-cli/).

В текущем Free-плане Tuna браузер при первом посещении видит собственное предупреждение с кнопкой «Посетить». Это происходит до загрузки приложения и не является нашей CAPTCHA. Ограничения формы не добавляют таких заданий. Проверка туннеля обычным API-клиентом подтверждает транспорт/страницу, но не отсутствие этого внешнего предупреждения: [официальное описание](https://tuna.am/en/docs/abuse/).
