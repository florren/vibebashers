# ADR-0030: ограниченный приоритет генерации решения HITL

Статус: принято, 10.11.2026.

## Причина

Отдельный semaphore продолжения графа после HITL не устраняет ожидание самого
LLM-решения оператора. В режиме `GIGACHAT_API_PERS` разные профили и credentials
делят один поток генерации процесса. FIFO ставит оператора за уже ожидающими
нормализацией, классификацией и решением новых сигналов. При непрерывном World
вход HITL может превышать скорость его разбора.

В запуске 7 за измеренные десять минут поступило 37 запросов и принято 28 решений.
В запуске 5 все 1443 HITL разобраны через live GigaChat, однако быстрый разбор
приходился на часы с существенно меньшей обработкой новых сигналов. Сравнение
этих интервалов само по себе не доказывает замедление inference модели.

## Решение

Единственный PERS-слот сохраняется, включая вложенный SDK-вызов и JSON repair.
Только генерация `bank_operator` получает отдельную очередь ожидания. При наличии
обычных запросов допускаются максимум два приоритетных вызова подряд; внутри
каждой очереди сохраняется FIFO. Выполняющийся запрос не прерывается. Отмена
ожидания или уже выделенного слота освобождает его для следующего запроса.

Deadline генерации по-прежнему начинается после получения слота. OAuth, ротация
credentials, provider balance, ограничения провайдера и учёт расхода сохраняются.
Остальные scopes, OpenAI-compatible, replay и mock не получают нового ограничения.
Решения и продолжения по-прежнему проходят через штатные HITL API/инструменты:
приоритет не является автоматическим согласованием и не меняет политики.

Пауза World сохраняет прежний смысл: автооператор World также приостановлен.
Ручные Journey/personal продолжают использовать собственные существующие контуры.
Сброс данных не нужен для применения исправления. Изменение не гарантирует
убывания очереди при произвольно высокой скорости генерации новых сигналов.

## Проверка и откат

Детерминированные тесты проверяют очередь под конкурирующим World, отсутствие
голодания обычных запросов, единственность генерации, отмену до и после выдачи
слота и передачу приоритета от роли через реальный ProviderChain. Существующие
проверки timeout/rotation сохраняются. Откат — предыдущий образ; миграций нет,
уже записанные данные и состояние часов не меняются.
