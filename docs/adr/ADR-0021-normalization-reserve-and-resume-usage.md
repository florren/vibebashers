# ADR-0021: бюджет нормализации и статистика продолжений агента

Дата: 31.10.2026. Принято по запросу пользователя после live-проверки PR #110.

## Проблема

Нормализация использовала context=fast_path: Lightning мог занять все 8 секунд,
после timeout основная модель не вызывалась. Получался mock даже при доступном Ultra.
Простое увеличение до 10 секунд на сравнительном наборе не устранило отказ:
оба бюджета дали 19/20 успешных ответов, первый кейс превысил оба лимита.

При resume_after_human создавался новый Deps с нулевыми tokens/cost/latency,
затем _finish перезаписывал полный итог AR статистикой только продолжения.
Тот же дефект был у resume_after_followup.

## Решение

- Отдельный context=normalization, общий дедлайн 10 секунд при наличии отличающейся
  основной live-модели. Первой модели доступна максимум половина бюджета (5 секунд),
  основной — оставшееся время. Timeout быстрой модели допускает переход к основной
  только для normalization. Уже существующее переключение после bad_output/unavailable
  сохраняется. Auth/quota/429 не вызывают повтор основной моделью.
- После исчерпания бюджета сохраняется честный штатный replay/mock с записью попыток.
  Fast_path=8, detector=5, batch=12, default=30 секунд не меняются.
- Оба resume восстанавливают токены и latency из сохранённых agent_steps, cost — из
  существующего cost_estimate, номер следующего шага и текстовый бюджет — из истории.
  Повторное продолжение не складывает прошлый итог повторно и не обнуляет его.
  Схемы/контракты и денежные политики не меняются.

## Проверка и ограничения

[Набор и результаты](../benchmarks/gigachat-normalize-hitl-2026-10-31/README.md):
20 текстов, baseline 8/10 секунд (40 попыток) и кандидат (20 попыток).
Кандидат: 20/20 валидных live-ответов GigaChat, максимум 5,644 с, p95 4,323 с;
12 Lightning, 8 Ultra, без mock/replay. Это последовательный тест текущего стенда,
не гарантия задержки при произвольной нагрузке или недоступном провайдере.
Переключение именно после timeout и общий дедлайн проверены детерминированно.

Стоимость старого испорченного AR не выводится из количества токенов: без исходных
тарифов и usage нельзя честно восстановить исторический cost. Сохраняем известный cost,
для новых продолжений он накапливается. Исправление счётчиков не повторяет граф/проводки.
