# ADR-0023: общая ускоренная цепочка публичного чата и аудит истории

Дата: 31.10.2026. Задача #131 и запрос о соответствии localhost:9999 экрану /journey.

Публичный процесс сохраняет прежнюю границу ADR-0017: принимает сообщения и читает
собственную историю; не получает LLM-ключи, Simulator или операторские API. При первом
входе после baseline/завершённого запуска он транзакционно создаёт paused live-run и
сохраняет общий профиль через app.demo.inputs.prepare. Основной worker подхватывает
новый указатель live-run без запуска часов и генераторов.

В ускоренную цепочку входят origin=jury и channel_subtype=ui_pers_demo. Оба проходят
те же инструменты, решения сотрудников, шаги команды и итоговые уведомления.
Ограничение частоты/антибот-проверка и требования к необходимым данным клиента
сохраняются; реальное время LLM не подменяется. Опоздание задаётся team_outcome=late,
а не текстом жалобы. При выключенной эмуляции сотрудников их решение остаётся ручным.

Исторический SIG-092812 завис после сохранённого reject: старый act создал followup
awaiting_team без инцидента. Reject теперь снимает followup, а act не создаёт ожидание
команды/проверки/отчёта без incident_id. Восстановление уважает исходный отказ: нет
нового фиктивного инцидента, возврата или подарка; клиент получает final_no_action_131.

scripts/history_audit.py по умолчанию только читает выбранный запуск и выводит
несовместимые product/error/run связи и orphan followup. Текст/контакты клиента не
попадают в отчёт. --run all явно расширяет аудит. Никакие связи массово не удаляются.
--repair-rejected SIG-N --run ID --apply разрешает только один сигнал без связанных
инцидентов, с отложенным ожиданием и подтверждённым reject. Advisory lock, аудит
старого состояния в agent_steps и сохранённый repair-run обеспечивают повторяемость
без повторных уведомлений. Неоднозначное состояние требует отдельного разбора.

Контракты, политики денег/HITL и схема БД не изменяются. Историческая коррекция
SIG-105875 выполнена ранее отдельно и остаётся в аудите 2197.

Отчёт содержит полные счётчики и до 200 примеров каждой категории. Различие продукта
при общем коде массового сбоя может быть корректным: это кандидаты для проверки,
а не основание автоматически удалять исторические связи.
