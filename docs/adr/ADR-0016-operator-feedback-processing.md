# ADR-0016 — поздние сведения влияют на дальнейшую обработку

Принято 30.10.2026 по уточнению заказчика, T-268 / GitHub #97. Уточняет ограничение ADR-0015: сохранения журнала недостаточно, сведения должен учитывать агент.

## Решение

Неизменяемый hitl_feedback остаётся источником текста/авторства/времени. Миграция 0010 добавляет отдельную очередь hitl_feedback_processing и включает существующие записи. Каждое дополнение получает самостоятельный agent_runs.kind=operator_review, graph_version=operator-feedback-v1 и шаг operator_feedback с входом, ответом модели, моделью/usage и вызовом инструмента. Исходный прогон не переисполняется.

Модель получает текст новых сведений, связанные инциденты и выполненные действия; строгий контракт operator_feedback задаёт summary_ru, priority и next_step. Детерминированный инструмент может повысить срочность открытого инцидента, добавить progress_report и адресную новую задачу manual_review/clarify_client. Снижение приоритета, автоматическое закрытие/переоткрытие, одобрение исходного HITL и денежные действия этим инструментом не выполняются. Для терминального инцидента создаётся closure_review без изменения статуса. Если инцидента ещё нет, создаётся ручная задача со ссылкой на сигнал. Это новый план работы по сведениям, а не повтор прежнего act.

Сведения и результат разбора включаются в контекст следующего decide и при восстановлении checkpoint после followup/ответа человека. Связи ограничены одним run_id и реальными incident_signals/agent_runs; общий клиент не расширяет область. Контекст ограничен последними 100 записями; полный журнал сохраняется отдельно. Наличие дополнения не считается формальным ответом на ожидающий HITL.

## Надёжность

Отдельный worker опрашивает PostgreSQL раз в 2 с, независимо от паузы симуляции и занятой очереди сигналов. Он использует текущую цепочку провайдеров, включая переключение live/replay/mock. Session advisory lock защищает одно дополнение от конкурентного разбора; соединение освобождает его при остановке. Эффекты, trace и отметка applied коммитятся вместе. До фиксации сбой откатывает всё; после фиксации повтор возвращает no-op. Прерванный предыдущий review отмечается failed, новый разбор не возобновляет его старые действия.

Ошибки не скрываются успешным статусом: failed/error видны в HITL, до трёх попыток с паузой 30 с. Даже неразобранный текст остаётся в дальнейшем контексте. Журнал, прежние decision/decided_by, agent_steps исходного графа, уведомления и ledger_entries не переписываются.

## Проверка

Интеграционные тесты проверяют изменение дальнейшего приоритета/задачи, изоляцию запусков, закрытый кейс, модельный контракт mock, сбой после внесения эффектов до commit, повтор и конкурентный разбор. UI показывает pending/applied/failed и ссылку на отдельный AR. Успешный model call подтверждается trace, а не самим фактом приёма текста.

## Откат

Предыдущая версия приложения игнорирует новую очередь. Downgrade 0010 не удаляет историю/очередь/разговоры; перед локальным обновлением сохраняются БД и image. Выполненные эффекты нового плана остаются историей инцидента.
