# ADR-0013 — Сравнение вариантов финансового эффекта запуска

Статус: принято для демонстрационного сравнения. Дата: 29.10.2026.
Основание: заказчик попросил учитывать все варианты на одном экране. Эпик E24, GitHub #87; реализация T-264/#88, продолжение T-265/#89.

## Решение

ADR-0007 остаётся источником основной модели: `potential = affected × detractor_share × no_return_share × (rate + premium)`, `prevented = potential × retention_factor`, `net = prevented − refund`. Основной итог — расчётная оценка, а не подтверждённая выручка. Отрицательный net не обрезается. Показ на /finance ограничен кейсами resolved/closed с временем решения; сам статус не доказывает удержание.

Рядом показаны две независимые сценарные оценки. Вторая — `1 × P / 100 × (rate + premium)` на идентифицированный кейс без исхода churned; P задаёт пользователь (по умолчанию 100 %), это не выход NLP. Без идентифицированного клиента оценка нулевая. Третья добавляет редактируемый условный штраф (по умолчанию пример из входа 50 000 ₽) один раз на решённый кейс misselling с хотя бы одним compliance_alerts.decision=go. go означает решение руководителя, а не доказанное предотвращение штрафа. Возвраты вычитаются из каждого варианта отдельно. Варианты не складываются. Повторные кейсы клиента могут пересекаться; оценки по кейсам не являются уникальным портфельным эффектом.

Ставка и премиальная надбавка берутся из сохранённого incident_economics, который вычисляет dcltv.py. Никаких новых ставок, изменений проводок, политик HITL и схемы БД. Для misselling сохраняется прежняя настраиваемая стоимость случая. Штраф не пишется в incident_economics или ledger_entries. Калиброванная вероятность NLP и доказательства предотвращения штрафа — открытая T-265.

## Время и доставка

GET /api/v1/finance/impact/total возвращает суммы, накопленный ряд и страницу реестра в одном repeatable-read read-only снимке. GET /api/v1/finance/impact/incident/{incident_id} читает сохранённые множители по числовому или публичному ID. Оба требуют один run_id (current или положительный id), all запрещён. Отсутствие current даёт пустой срез, не все запуски. Неизвестный запуск/чужой кейс — 404. По умолчанию Live охватывает весь запуск; день UTC, неделя — текущий день и 6 предыдущих, месяц — текущий день и 29 предыдущих относительно sim_state.sim_time. Произвольные даты с часовым поясом образуют полуинтервал [start, end), максимум 366 дней. При просмотре старого запуска календарные фильтры по-прежнему относятся к общим сим-часам; Live или даты позволяют открыть весь исторический запуск.

Один инцидент — одна строка; EXISTS по алертам исключает умножение. Сценарий округляется до копеек на кейс до суммирования. Временной ряд — реконструкция по текущим сохранённым расчётам и времени решения, а не неизменяемый журнал признания дохода; после калибровки/переоткрытия он может изменяться. Неполные/устаревшие расчёты отмечаются счётчиками, итоги предварительные; GET не маскирует проблему пересчётом или нулями без предупреждения.

Источник compute_incident публикует metrics/FINANCIAL_IMPACT_UPDATED только при изменении breakdown. Оболочка WS остаётся topic/type/ts/data/run_id, вместо второго протокола из документа. Клиент перечитывает REST-снимок, не прибавляет дельту: повтор события не удваивает деньги; переподключение и polling 5 с восстанавливают пропуски. Смена текущего запуска меняет ключ запроса; анимация не переносит сумму старого запуска. При prefers-reduced-motion анимация отключена.

## Ограничения и откат

Не доказываем предотвращённый регуляторный штраф, остановку сделки и причинный вклад агента в удержание без дополнительных данных. Производительность на профиле demo и NRT ≤ 1 с требуют измерений под нагрузкой. Новых зависимостей и миграций нет. Откат — revert PR; старые API/дашборд и сохранённые расчёты совместимы.
