# csi_v1 — демонстрационные данные

300 синтетических жалоб на обслуживание; 120 совместных корзин посещений
(10 ВСП × 4 корзины ожидания × 3 корзины перенаправлений), всего 2400 визитов.
`employees.json` содержит 60 fixture-привязок сотрудников без ФИО/контактов;
жалобы принадлежат 30 сотрудникам с меньшим стажем. Это специально заданная
демонстрационная зависимость, а не наблюдаемая причинность и не calibration
runtime-поведения клиентов.

Источник: `data/csi_params.yaml`, `data/branches.yaml`,
`backend/app/sim/csi_corpus.py`; генератор использует `SimRng` с seed42.
Веса задают фиксированные числа жалоб по совместным корзинам; RNG меняет
текст, время, параметры обслуживания и распределение по сотрудникам.
Интервалы ожидания: [0,5), [5,15), [15,30), [30,60) минут;
корзины перенаправлений: 0, 1, 2–4. Стаж соответствует стандартному свежему
seed с anchor 2026-11-09T09:00:00+03:00. Окно наблюдения — тот же день
09:00–17:00; его границы не являются текущими часами рабочего стенда.

## Воспроизведение

```bash
backend/.venv/bin/python scripts/seed/gen_csi_corpus.py --import-output data/import/csi/csi_v1
```

JSON и XLSX содержат одинаковые CSI IDs; повторная загрузка должна дать
дубли, а не дополнительные сигналы. XLSX и ZIP metadata детерминированы.
Каталог `data/import/csi/csi_v1` содержит только импортируемые жалобы;
metadata/visits/employees нельзя передавать в `/api/ingest/csi`.

EMP IDs принадлежат fixture чистого стандартного seed. Перед ручным импортом
в собственный тестовый стенд выполнить read-only проверку roster:

```bash
backend/.venv/bin/python scripts/seed/gen_csi_corpus.py --check-db --import-output data/import/csi/csi_v1
# DATABASE_URL_TEST должен указывать на собственную изолированную fixture.
make import-csi FILE=data/import/csi/csi_v1 CX_BASE_URL=http://localhost:8000
```

При несовпадении branch/desk/public_id/position/стажа preflight завершается
ошибкой до создания файлов. Нельзя подменять сотрудников либо их стаж для
успешного импорта. Проверка не является блокировкой последующего HTTP-запроса:
между preflight и импортом fixture должна оставаться неизменной.

`visits.json` относится только к этой синтетической когорте и её окну.
Этот пакет не записывает знаменатели в глобальную `csi_visits_agg`: у неё
пока нет run/cohort provenance. Связывание и безопасная загрузка знаменателей
остаются обязательной частью T-247/T-248 до готовности вероятностного API.
Нельзя делить произвольные импортированные жалобы другого run на эти визиты
или считать отсутствующие знаменатели нулевыми. Формулы dCLTV и рабочие
параметры клиентов этим набором не меняются.
